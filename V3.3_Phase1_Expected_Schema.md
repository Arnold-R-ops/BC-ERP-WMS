# BC ERP-WMS V3.3 Phase 1 - Expected Database Schema

## Overview

This document defines the expected database schema after successful V3.3 Phase 1 migration.

## Table: product_spu (NEW)

### Purpose
Product SPU (Standard Product Unit) table for managing product families/series.

### Columns

| Column Name | Data Type | Nullable | Default | Constraints | Description |
|------------|-----------|----------|---------|-------------|-------------|
| id | BIGINT | NO | nextval('product_spu_id_seq') | PRIMARY KEY | Auto-increment ID |
| spu_code | VARCHAR(50) | NO | - | UNIQUE | SPU unique code |
| spu_name | VARCHAR(200) | NO | - | - | SPU name (product family name) |
| category | VARCHAR(100) | YES | NULL | - | Product category |
| brand | VARCHAR(100) | YES | NULL | - | Brand name |
| description | TEXT | YES | NULL | - | SPU description |
| enabled | BOOLEAN | NO | true | - | Whether enabled |
| created_at | TIMESTAMP | NO | CURRENT_TIMESTAMP | - | Creation timestamp |
| updated_at | TIMESTAMP | NO | CURRENT_TIMESTAMP | - | Update timestamp |

### Indexes

| Index Name | Columns | Unique | Description |
|-----------|---------|--------|-------------|
| product_spu_pkey | id | YES | Primary key |
| product_spu_spu_code_key | spu_code | YES | Unique constraint on spu_code |
| idx_spu_code | spu_code | YES | Index for quick lookup by code |
| idx_spu_name | spu_name | NO | Index for searching by name |
| idx_spu_category | category | NO | Index for category filtering |

### Default Data

Must contain at least 1 row:

```
id = 0
spu_code = 'DEFAULT-SPU'
spu_name = 'Default Product Family (Legacy Data)'
category = 'Uncategorized'
enabled = true
```

### Sequence

- Sequence name: `product_spu_id_seq`
- Next value: Should be >= 1 (after inserting ID=0)

## Table: products (MODIFIED)

### New Columns Added

| Column Name | Data Type | Nullable | Default | Constraints | Description |
|------------|-----------|----------|---------|-------------|-------------|
| spu_id | BIGINT | NO | - | FK → product_spu(id) | Foreign key to product_spu |
| sku_name | VARCHAR(100) | NO | - | - | SKU-specific name |
| specs | VARCHAR(500) | YES | NULL | - | Specification description |

### Foreign Key Constraints

| Constraint Name | Column | References | On Delete | On Update |
|----------------|--------|------------|-----------|-----------|
| fk_product_spu | spu_id | product_spu(id) | RESTRICT | CASCADE |

### New Indexes

| Index Name | Columns | Unique | Description |
|-----------|---------|--------|-------------|
| idx_spu_id | spu_id | NO | Index on spu_id for FK lookups |

### Data Requirements

After migration:
- All existing products must have `spu_id = 0` (pointing to default SPU)
- All existing products must have `sku_name` populated (copied from `name` field)
- `specs` can be NULL

## Table: inventory_batch (MODIFIED)

### New Columns Added

| Column Name | Data Type | Nullable | Default | Constraints | Description |
|------------|-----------|----------|---------|-------------|-------------|
| location_code | VARCHAR(50) | NO | - | - | Location code string (redundant field) |

### Constraint Changes

**REMOVED**:
- Unique constraint on `batch_code` (was preventing multi-location batch support)

### New Indexes

| Index Name | Columns | Unique | Description |
|-----------|---------|--------|-------------|
| idx_batch_code | batch_code | NO | Non-unique index on batch_code |
| idx_batch_location | batch_code, location_code | NO | Composite index for batch-location queries |
| idx_location_code | location_code | NO | Index on location_code |

### Data Requirements

After migration:
- All records must have `location_code` populated
- Records with valid `location_id` should have `location_code` synced from `locations` table
- Records with NULL `location_id` should have `location_code = 'PENDING'` or `'UNASSIGNED'`

## Common Issues and Solutions

### Issue 1: "字段 spu_code 不存在"

**Root Cause**: product_spu table either:
- Doesn't exist at all
- Exists but has wrong column names (e.g., `code` instead of `spu_code`)

**Solution**:
1. Run Step 1 of Database_Diagnosis.sql to check if table exists
2. If exists, run Step 2 to check column names
3. If column names are wrong, DROP and recreate table using V3.3_Migration_Simple_Step_by_Step.sql

### Issue 2: Foreign Key Constraint Violation

**Root Cause**: Attempting to add FK constraint before data cleaning

**Solution**:
- Ensure Step 4 (data cleaning) runs BEFORE Step 5 (adding constraints)
- All products must have `spu_id = 0` before adding FK to product_spu

### Issue 3: Sequence Not Found

**Root Cause**: Table created without proper BIGSERIAL or IDENTITY column

**Solution**:
```sql
-- Check if sequence exists
SELECT sequence_name FROM information_schema.sequences WHERE sequence_name = 'product_spu_id_seq';

-- If not, create it
CREATE SEQUENCE IF NOT EXISTS product_spu_id_seq;
ALTER TABLE product_spu ALTER COLUMN id SET DEFAULT nextval('product_spu_id_seq');
```

### Issue 4: Cannot Insert ID=0

**Root Cause**: Column defined as GENERATED ALWAYS AS IDENTITY

**Solution**:
```sql
-- Change to GENERATED BY DEFAULT
ALTER TABLE product_spu ALTER COLUMN id DROP IDENTITY IF EXISTS;
ALTER TABLE product_spu ALTER COLUMN id ADD GENERATED BY DEFAULT AS IDENTITY;
```
