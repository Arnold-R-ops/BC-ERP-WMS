## 验收范围

本批次交付独立于办公管理端的仓库移动作业界面：

1. 到货收货：核验商品或批次、核验目标库位、录入实收数量并完成整单收货。
2. 出库拣货：按后端返回的路径顺序执行任务，兼容批次标签扫码与无码库位识别两种模式。
3. 盲盘计数：扫描库位、批次或商品后录入现场实数，计数阶段不显示账面库存。
4. PWA 应用壳：采用响应式手机网页/PWA，不开发独立原生 App；生产构建可安装到手机桌面。网页自身必须保留应用标题栏和导航，不依赖微信或浏览器的 `×`、`…`；断网可保留已加载界面，但禁止提交任何库存变更。

## 启动条件

- 后端：`http://127.0.0.1:8080`
- 前端：`http://127.0.0.1:5173`
- 数据库已应用 Flyway `V4_28__Warehouse_Mobile_Operation_Permissions.sql`。
- 使用 `SUPER_ADMIN`、`WAREHOUSE_ADMIN` 或 `WAREHOUSE_STAFF` 账号登录。
- 桌面端从左侧“仓库作业”进入；手机端从网页自身的汉堡菜单或工作台“仓库作业”快捷卡进入。直接地址仅用于故障排查，不作为正常操作入口。
- 扫码枪可使用键盘输出模式：扫码后发送回车，无需安装浏览器插件。

## 验收步骤

### 1. 移动入口与权限

- 仓库管理员、仓库员工和超级管理员能够进入移动作业。
- 销售员、采购员和总经理默认无该模块入口，直接访问时返回工作台。
- 约 430px 手机视口必须显示固定的网页应用标题栏和汉堡菜单；点击后从左侧打开按当前角色权限过滤的完整导航抽屉，选择路由后自动关闭。
- 导航抽屉中的“仓库作业”可展开“收货 / 拣货 / 盘点”；工作台同时提供仓库作业快捷卡，两个入口指向同一组页面。
- 页面顶部显示当前账号、角色和联网状态；底部固定显示“收货 / 拣货 / 盘点”。
- 以约 430px 宽手机视口查看，页面不得横向滚动，字段、按钮和底部导航不得相互遮挡。

### 2. 到货收货

- 进入“收货”，只列出 `AWAITING_RECEIVAL` 的入库订单。
- 扫描商品主条码、内部批次码或外部批次码后，只能识别当前订单中的明细。
- 扫描错误库位时明确提示目标库位，不能将该明细标记为已核验。
- 全部明细的商品与库位均核验后，“确认整单收货”才可使用。
- 确认成功后，订单从待收货列表消失，后端继续负责库位防混放、批次落账和库存事务。

### 3. 出库拣货

- 进入“拣货”，显示 `PENDING` 与 `PICKING` 任务，并保持后端提供的二维库位路径顺序。
- 每个任务先扫描目标库位；库位不匹配时不能进入下一步。
- `PRINTED_LABEL` 商品要求继续扫描批次标签，提交 `batchCode`。
- `LOCATION_VISUAL` 商品要求扫描商品主条码，提交 `locationId + skuCode`，批次由后端在唯一合法库位库存中反查。
- 实际数量不得超过任务计划数量；确认后继续由后端核销预留、扣减批次库存并推进订单履约状态。

### 4. 盲盘计数

- 进入“盘点”，只列出 `COUNTING` 状态任务。
- 页面只能看到商品、商品条码、批次和库位，不得显示快照数量、差异数量或账面库存。
- 同一库位命中多条明细时，系统不得自动猜测；必须继续扫描批次码或商品条码，直到唯一匹配。
- 每项可录入大于等于 0 的现场数量；全部明细完成前不得结束任务。
- 点击“完成本次盘点”后任务进入复核阶段，差异审批仍在办公管理端进行。

### 5. 离线边界与安装

- 生产环境打开一次后，可由浏览器“添加到主屏幕/安装应用”。
- 断网时页面显示明确警告，收货、拣货、盘点保存与完成按钮均不可用。
- Service Worker 不缓存 `/api`，系统不保存或重放离线库存写请求，避免恢复网络后重复扣减。
- 恢复网络后操作按钮重新启用，并重新读取服务器当前状态后再继续作业。

## 当前边界

- 本批次使用扫码枪键盘输入，不包含摄像头扫码、OCR 或原生 PDA SDK。
- 收货沿用现有后端“整单完成”接口，不伪造部分收货状态。
- 离线仅用于应用壳与已加载页面展示，不支持离线收货、离线拣货或离线盘点提交。
