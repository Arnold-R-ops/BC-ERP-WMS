# 租户 ERP 管理端页面规格书

> 本文已按 P0-02、P0-03B/C/D、P0-04A/B/C 实施结果收口。字段、枚举和路径以当前 `openapi.json` 为准；实施报告负责解释业务规则，本文只描述页面意图和关键交互。旧采购直接收货、旧四步入库和销售混合状态不再是有效规格。
> 通用约定：列表页 = ProTable（查询表单+分页+列设置）；详情用抽屉或详情页均可但全站统一。

## 0. 全局布局

- ProLayout 侧边菜单，顶栏右侧：语言切换（中/EN）、当前角色徽标（点击可切换角色，调 switch-role）、用户菜单（改密码、登出）
- 租户主页面菜单按权限显示：工作台、商品与主数据、库存查询、销售订单、销售退货、采购管理、其他入库申请、出库作业、调拨管理、库存治理、仓储配置、渠道集成、IAM 和经营分析。
- “收货”属于独立仓库工作区；从租户主页面进入后使用适合手机的仓库页面，右上角返回电脑端。采购管理和其他入库申请仍在租户主页面内操作。

## 1. 工作台（Dashboard）

四个待办卡片（数字角标 + 点击跳转对应列表的预筛选视图）：

| 卡片 | 数据来源 |
|---|---|
| 待审批销售订单 | `GET /api/sales-orders?commercialStatus=PENDING_APPROVAL` 取条数 |
| 待映射 SKU | `GET /api/integration/sku-mappings/pending` 取数组长度 |
| 待人工复核渠道事件 | `GET /api/integration/raw-events?status=MANUAL_REVIEW` 取 totalElements |
| 紧急补货建议 | `GET /api/predictions/reorder/urgent` 取条数 |

下方两个快捷列表：最近待审批订单（前 5 条，行内审批入口）、紧急补货商品清单。

## 2. 商品管理运营台

### 2.1 产品（SPU）

- 列表：`GET /api/products`，展示产品编码、名称、品牌、二级类别、SKU 启用比例和状态。
- 新建/编辑：`POST /api/products` / `PUT /api/products/{id}`；产品绑定当前前端可选的二级类别。
- 产品编码是稳定业务编码；停用产品会级联停用其 SKU，重新启用产品不会自动启用 SKU。
- 每行“管理 SKU”打开该产品的规格抽屉。

### 2.2 产品 SKU

- 列表：`GET /api/product-skus?productId={productId}`；SKU 是库存、采购、销售、履约和渠道映射的最小业务单元。
- 新建/编辑：`POST /api/product-skus` / `PUT /api/product-skus/{id}`，维护主条码、规格、价格、箱规换算、临期阈值、安全库存和批次追踪模式。
- `skuCode` 由系统生成、不可修改且永不复用；`barcode` 是当前实物包装的唯一主条码，两者不可混用。
- 当前不提供物理删除，采用启用/停用控制新业务是否可选。

### 2.3 产品类别

- 类别树：`GET /api/categories/tree`；创建、编辑、移动、启停和删除分别使用 `/api/categories` 下的对应端点。
- 后端 `parentId` 支持任意深度；当前管理端只允许维护一级、二级类别，产品必须绑定二级类别。

## 3. 库存三层穿透查询（只读）

三层钻取，是仓库日常最高频页面：

1. **SKU 汇总层** `GET /api/inventory/summary?page=&search=`：每行显示在库、销售预留、可售可用、在途、公司拥有数量及质量状态分布。可售可用必须使用服务端对 `AVAILABLE`、有效库存行、效期和各类预留的统一计算，前端不得再用“在库－预留”自行推导；公司拥有数量为各仓实存加在途 → 点击行进入第 2 层
2. **批次明细层** `GET /api/inventory/details/{skuId}`：该商品全部活跃批次（批次码/效期/库位/数量），效期临近的行黄色预警、已过期红色
3. **库位反查层** `GET /api/inventory/location/{locationCode}`：输入/扫描库位码，显示该库位上所有批次——做成第 1 层页面顶部的快捷搜索框（按库位查）

## 4. 销售订单：四层状态

- 列表调用 `GET /api/sales-orders`，默认分别展示业务主状态 `commercialStatus`、库存分配 `allocationStatus`、仓库进度 `warehouseStatus` 三列并支持独立筛选；物流进度 `logisticsStatus` 主要在详情内展示，禁止重新拼成单一“订单状态”。
- 创建时明确区分“保存草稿”和“提交订单”。草稿可编辑或删除且不分配库存；提交后才按租户策略进入直接批准或待审批。
- 审批策略支持 `DIRECT`、`RISK_BASED`、`ALWAYS`，普通租户默认 `DIRECT`。待审批期间不分配；批准后由服务端幂等执行库存分配，并独立汇总已分配、部分分配、欠货或等待入库。
- 详情展示订单行、审批证据、分配/欠货、仓库任务、发货证据和物流时间线。客户端不能直接提交任何状态值。
- 未开始拣货的已批准订单可取消并释放预留；部分发货后只能关闭未发剩余；作废只用于没有预留、任务、发货或库存流水的错单，所有动作均要求当前 OpenAPI 规定的原因、版本和幂等键。
- 仓库“确认发货”才实际消耗预留并扣减库存；不得再使用旧“确认拣货即发货”的文案或 `/confirm`、`/batch-confirm` 路径。
- 基础承运商和运单信息仍可维护；详细物流生命周期由租户开关控制，默认关闭。

## 5. 采购管理与 ASN

- 创建或导入采购草稿后，每一采购行必须先把全部计划数量分配到目标仓库；允许同一行按数量拆到多个仓库，分仓合计不等于订购数量时不能提交。
- 采购提交后，普通租户按 `NONE` 直接生效；具备对应能力且启用 `SIMPLE` 的租户才进入采购审批。采购审批和短收余量关闭是两个独立策略。
- 生效后系统按目标仓库建立 `WAITING_SHIPMENT` 收货计划。采购人员可在采购页面使用“确认发货”快捷操作，由系统原子创建并确认 ASN；复杂场景可进入 ASN 草稿管理。
- 一张采购单可有多张 ASN；一张 ASN 只属于一个采购单和一个目标仓库，可包含多个 SKU，累计数量不能超过该分仓的可发数量。
- ASN 未收货时可取消或纠错重建；发生收货后不得修改或取消，只能按策略关闭未收到的剩余数量。
- 采购页面只提供“查看/进入收货任务”，不提供直接收货、采购回退或客户端填写操作人的旧接口。

## 6. 统一收货与其他入库申请

### 6.1 仓库统一收货

- 采购 ASN 确认、允许的其他入库申请确认后都生成统一收货任务；仓库通过 `GET /api/receiving-tasks` 查询授权仓库内的任务。
- 仓库人员按登录账号识别，在独立收货工作区为每次实收选择库位、数量，并按 SKU 效期规则填写批次、生产日期和有效期；客户端不得提交操作人。
- 使用 `POST /api/receiving-tasks/{id}/receipts` 分批或分库位收货。每次提交全部原子执行，任一行失败时批次、库存流水、收货事件和来源单状态全部回滚。
- 禁止超收。未启用效期管理的普通商品可不填生产日期/效期；启用时必须按规则填写。
- 收货后是否直接 `AVAILABLE` 由当前质检策略和 SKU 设置决定：免检直接可售，需要质检的库存进入 `PENDING_INSPECTION`。

### 6.2 其他入库申请

- `/inbound` 当前表示“其他入库申请/无采购入库申请”，不是采购收货，也不是仓间调拨。
- 功能由租户管理员单独开启；使用 `/api/other-inbound-applications` 创建、编辑、确认和终结申请，确认后同样进入统一收货，不直接落账。
- 功能关闭后禁止新建、编辑和确认，但必须保留历史及在途申请的查询和受控终结操作。

## 7. 库存治理与质检

- “库存治理”分别提供盘点、质量冻结/恢复、收货质检、库存处置和紧急校正页面，不提供可任意改写质量状态的通用按钮。
- 质量冻结不减少实存，但会把数量移出可售；恢复默认 `DIRECT_WITH_REASON`，租户可独立切换为双人审批。
- 收货质检默认关闭；SKU 可设 `INHERIT`、`REQUIRED`、`EXEMPT`。需要质检时在原收货库位完成，合格放行默认直接执行，也可开启复核。
- 库存处置默认填写原因后进入待执行，审批可选。质检和处置当前都不包含照片/附件上传，不能把图片列为提交必填项。

## 8. 销售退货 RMA

- 租户主页面的 `/rmas` 用于基于原销售、原出库明细创建正式 RMA，并处理审批、关闭剩余、退款资格、退款/换货、策略和渠道退款待办；不提供无订单退货。
- 仓库退货作业在独立仓库工作区执行收货和逐数量质检，只展示安全作业字段。
- RMA 默认直接授权，商业退货期默认 5 天；仅退款、提前退款/换货和隔离暂存均默认关闭。
- 退货收货创建新批次与 `RETURN_IN` 流水，不直接改回原出库批次；质检结果可进入可售、破损、隔离或拒收。

## 9. 多仓调拨

- 租户主页面 `/transfers` 管理同一租户内不同仓库之间的调拨；独立仓库工作区按调出、调入两个任务页签执行。
- 页面分别展示业务主状态、调出状态和调入状态。默认直接批准，也可开启始终审批；来源仓只分配 `AVAILABLE` 库存。
- 调出形成 `TRANSFER_OUT` 和在途数量；调入必须选择目的库位并形成新目的仓批次与 `TRANSFER_IN`。在途不进入任一仓 ATP。
- 支持分批调出、分批调入、多个目的库位及受控差异关闭；错货不落账、超收禁止，错误事实通过反向调拨更正。

## 10. 渠道集成现有页面

> 当前店铺配置、SKU 映射、待映射、原始事件复核和对账仍是租户主页面内的独立页面。统一“渠道运营工作台”属于后续开发，不得把本节描述成已经完成的新工作台。Shopify 保持只读，首次试点的自动轮询和自动对账默认关闭。

### 10.1 店铺配置
- 列表/新建/编辑：`/api/integration/configs`（密钥字段显示为掩码，编辑时留空=不修改——界面加说明文字）
- **测试连接**按钮：`POST /{id}/test-connection`，成功显示店铺名/币种/时区
- 手动同步按钮（页面顶部）：`POST /api/integration/shopify/sync`，返回 成功/跳过/失败 计数 toast

### 10.2 待映射队列（核心页面）
- 列表：`GET /api/integration/sku-mappings/pending`（默认 status=PENDING，按卡单次数倒序）
- 每行展开卡片：外部 SKU、商品标题、样例单价、卡单次数、样例订单号
- 右侧操作区：
  - 候选推荐 `GET /pending/{id}/suggestions`（单选列表，展示 条码+名称）
  - 或手动搜索商品（复用商品列表接口）
  - 数量换算比输入框（默认 1，帮助文案：“1 个渠道单位 = N 个内部单位”，>1 时显示预览：“顾客买 1 件 → 仓库发 N 件”）
  - 三个动作按钮：**确认映射**（action=MAP+productId+ratio）/ 标记虚拟行（VIRTUAL，说明“运费/服务费等不占库存的行”）/ 忽略（IGNORE）
- resolve 成功后 toast：“已映射。被卡订单将在下次同步自动放行”，并提供“立即同步”快捷按钮（调 sync）
- `NOSKU::` 前缀的行加特殊徽标“无 SKU 行”

### 10.3 SKU 映射管理
- 列表 `GET /api/integration/sku-mappings?channel=`：外部SKU → 内部商品、换算比、类型（PRODUCT/VIRTUAL）、来源（AUTO 自学/MANUAL）、状态
- 编辑（改商品/换算比/停用启用）`PUT /{id}`；手动新建 `POST`

### 10.4 人工复核列表
- `GET /api/integration/raw-events?status=MANUAL_REVIEW`（分页）：事件类型（渠道取消/渠道改单）、外部单号、原因说明、时间
- 行点击 → 详情抽屉 `GET /{id}` 展示原始 JSON（格式化+可复制）
- V1 只做“查看+知晓”，处理动作（改单/退货）由人工在对应订单页操作——抽屉里放“跳转本地订单”链接（按 externalId 查销售订单）
- FAILED Tab 一并提供（失败原因排查用）
