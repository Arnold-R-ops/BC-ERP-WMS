# 租户 ERP：P0-04C 后续阶段与上线 A/B 选项框架

- 日期：2026-09-01
- 适用基线：完成 P0-01～P0-04C 的本地开发和自动化验证后
- 用途：供用户选择后续路线，不代表已经授权合并、推送、部署或开始下一 Epic。

> 本文的“选项 A / 选项 B”是本次上线策略选择，不是原交接文档中旧的“阶段 A / 阶段 B”。

## 1. 当前所处位置

原交接中的以下核心业务风险已通过 P0-01～P0-04C 完成主要开发：库存统一记账与幂等基础、采购治理与统一收货、库存质量/冻结/召回/质检/处置、销售四层状态、销售退货 RMA、多仓调拨。

按原编号，已经覆盖 `DEC-01`～`DEC-05`、`DEV-01`、`DEV-04`、`DEV-05` 和 `DEV-09` 的主要目标。`DEC-08` 已确认真实设备验收延期：现阶段可以用手机浏览器做页面与摄像头扫码预验收，但手持终端、扫码枪、标签打印机和面单打印机只有在设备到位且对应功能启用后才能正式验收。

仍有 13 个原 `DEV` 项和 2 个治理/信息架构项未完成；其中 `DEV-07` 应拆成四个独立任务，因此实际至少是 18 个可单独确认的交付切片。这些大多属于 P1/P2 产品成熟度，不应全部自动升级为核心版上线前置条件。

但“主要 P0 业务已开发”不等于“所有库存写入口和开户基线已经收口”。P0-01 的原始边界明确把销售出库、盘点等逐域迁入 `InventoryPostingService` 留给后续任务；当前公共预留释放入口也仍需确定最终用途、权限和审计。这些属于 A/B 共同的上线封口，不是可无限延期的高级功能。

## 2. 两个选项共同的上线门禁

无论选择 A 还是 B，正式上线前都必须完成同一组发布门禁：

1. **P0 库存写入口残余封口**：逐项复核销售出库、盘点和公共 `POST /api/inventory/reservations/{id}/release`；确认唯一业务来源、方法级权限、公司/仓库范围、幂等、审计和锁规则，并迁入统一记账边界或形成有证据的等价权威实现。
2. **新租户业务基线封口**：确认另一平台任务中的“可版本化、可幂等重放的租户业务基线初始化器”已经覆盖全部启用权限、系统岗位、角色继承和默认映射；未完成时只能使用人工初始化的受控试点租户，不能开放自助开户后直接经营。
3. **提交整合审计**：按 P0-01～P0-04C 顺序合并，检查迁移版本、冲突、OpenAPI/TypeScript 漂移和生产构建；合并、推送仍需单独授权。
4. **生产结构迁移彩排**：在隔离的生产结构/真实数据副本上演练完整 Flyway 链，明确历史 `V4.73` 校验和处置，核对迁移前后库存总量、预留、在途、单据和权限；不得直接用生产库试错。
5. **多租户与低权限数据库验收**：至少两个租户覆盖业务 Controller、异步任务、Webhook、导入导出和异常线程；应用角色必须为非 `SUPERUSER`、非 `BYPASSRLS`。
6. **保留专用测试租户**：上线后保留与生产租户隔离的测试租户和测试角色，用于每次发布前后的非破坏性冒烟测试。
7. **目标环境安全**：最终域名、TLS、可信 Host、CORS/反向代理、正式 SMTP、密钥/秘密管理、最小权限数据库账号、日志脱敏和生产 OpenAPI/Swagger 关闭全部验收。
8. **运维恢复能力**：完成备份、恢复或 PITR 演练、监控告警、迁移失败处理和版本回退预案。
9. **端到端 UAT**：覆盖采购、统一收货、质检、库存处置、销售、出库、RMA、调拨、盘点、IAM 和平台开户；手机可参与页面/摄像头扫码预验收。
10. **设备功能门禁**：在没有真实手持终端和打印机时，对应打印/设备功能保持关闭或不纳入本次承诺，不能用模拟测试宣称真实设备已验收。
11. **文档真相收敛**：以后续已确认实施报告为准，清理旧方案中“采购审批默认开启、解冻强制审批、破损/销毁强制照片”等已被新决策替代的描述，避免上线验收使用旧规则。

## 3. 选项 A：核心版先进入受控试点验收

### 路线

1. `A1 统一发布候选审计`：整合当前 P0 分支，执行全部共同门禁的自动化部分。
2. `A2 测试租户与手机 UAT`：按角色、仓库和两租户执行端到端业务验收，修复阻断上线的问题，不扩展新产品范围。
3. `A3 生产准备与受控试点`：配置正式环境、恢复演练和上线检查；得到单独授权后，仅让少量内部或熟悉的目标租户使用。
4. `A4 上线后按真实需求增量开发`：从剩余清单中逐个确认，不要求一次完成全部 P1/P2。

### 首次上线接受的边界

- 缺拣、复核、装箱、重量、标签和承运商仍可能依赖人工流程。
- 不提供多仓 SKU 补货策略、调拨建议、在途 ATP、波次、路径优化或自动盘点。
- 不提供正式采购单 PDF、模板管理中心、完整成本利润、B2B 客户价或第二渠道。
- 渠道仍使用现有技术对象页面，统一“渠道运营工作台”在主租户页面内后续开发。
- 真实打印机和手持终端验收延期；未验收能力不得对租户宣传为已支持。

### 适用条件

选择 A 的前提是首批租户单量可控，能够接受上述人工 SOP 或暂缺能力，且核心诉求是采购、库存、销售、退货、调拨和基础渠道订单闭环。它的优势是尽早获得真实租户反馈、缩小首次发布回归面；代价是高端仓库和经营分析能力需要上线后继续补齐。若拣配错误、跨仓策略依赖、渠道异常积压、业务日期偏差或人工对账已经不可承受，应停止扩大试点并转入选项 B。

## 4. 选项 B：上线前继续补齐产品能力

选项 B 不建议把所有剩余事项塞进一个大版本；应按下面五个阶段逐项确认，每个 Epic 仍需单独业务设计、权限、迁移和验收。

### B1 仓库履约与单据完善

- `DEV-06`：缺拣、错拣、破损、复核、包装、箱号、重量、拆单/合单、面单边界。
- `DEV-02`：正式采购单 PDF/Excel、版本和打印历史。
- 真实标签/面单打印只有设备到位后才纳入验收；无设备时可先开发并保持功能开关关闭，但不能完成真实打印验收。

### B2 多仓计划与自动化

- `DEC-06`：SKU 停用、重新启用、剩余库存和开放单据治理。
- `DEV-10`：公司 + SKU + 仓库经营策略，明确安全库存、补货点和提前期语义。
- `DEV-03`：补货建议生成采购草稿，不直接确认或改库存。
- `DEV-07A`：是否以及如何把在途库存纳入 ATP。
- `DEV-07B`：波次生成与任务合并。
- `DEV-07C`：拣选路径优化。
- `DEV-07D`：储存位到拣选位的仓内补货任务；这也承接此前确认“后续仓内移动”的独立流程。
- `DEV-08`：周期/ABC/风险触发的自动盘点调度。

### B3 运营工作台、国际化与首页

- `DEC-07`：在租户主页面内建立独立“渠道运营工作台”，统一未知 SKU、客户不匹配、重复订单、失败重试和人工复核待办；不是跳出主系统的仓库独立工作区。
- `DEV-14`：公司业务时区、默认语言、用户显示偏好和全局业务日切；当前 `Europe/London` 仅覆盖已经接线的部分业务规则，不等于全局 Localization 已完成。
- `DEV-17`：按仓库、销售、采购和管理层提供角色化首页与待办。

### B4 经营与商业能力

- `DEV-13`：先确认成本法、退货、税费、运费和汇率口径，再开发毛利/利润。
- `DEV-12`：B2B 门户、客户等级价和阶梯价。
- `DEV-11`：导入模板管理中心；此前已确认延期，可继续放在本阶段末尾。

### B5 渠道与生产基础设施

- `DEV-15`：按真实订单占比选择第二渠道；对象存储、Redis、秘密管理和只读副本分别评估，不与渠道接口强行捆绑。
- `DEV-16`：选择一个真实 Domain Outbox 消费者，补齐发布、重试、顺序、死信、监控和消费幂等。
- 完成 B1～B5 中用户实际选择的范围后，再执行第 2 节的统一上线门禁。

## 5. 独立延期项

以下事项此前已经明确延期或尚未确认方案，不能因选择 A 或 B 就自动视为完成：AQL 自动判定、质检图片/附件及对象存储、质量专用库位与额外仓内移动、退供应商/返工、已发货召回深化、无单退货、维修/保修、退货标签、自动支付退款，以及完整的手机/手持终端/扫码枪/标签打印机/面单打印机验收。

它们是否阻断首发，取决于首批租户的业务承诺和适用监管场景；选择路线时应把未纳入项写进产品边界和线下替代流程，而不是默认支持。

## 6. A/B 对比

| 对比项 | 选项 A：核心版先验收上线 | 选项 B：继续扩展后上线 |
|---|---|---|
| 首次上线范围 | 已完成 P0 核心闭环的受控试点 | P0 + 用户选定的 P1/P2 |
| 上线前开发阶段 | 不再新增产品 Epic，只修发布阻断项 | 最多 5 个阶段，实际范围逐项确认 |
| 仓库成熟度 | 可运行，但包装、标签、波次等可能人工处理 | 可按目标客户补齐更完整的仓库作业 |
| 经营/渠道体验 | 保持当前能力，后续增量升级 | 可先完成工作台、利润、B2B 或第二渠道 |
| 回归和迁移范围 | 较小 | 较大，新增阶段越多风险面越大 |
| 真实反馈 | 更早 | 更晚，但首发功能更完整 |
| 适合情形 | 首批租户重视核心进销存闭环，并可接受人工辅助 | 首批已签约客户明确要求高级仓库或商业能力 |

## 7. 建议选择口径

在尚无首批客户明确要求波次、包装/面单、B2B 价格或完整利润报表的情况下，建议以 **选项 A** 为默认参考：先完成统一上线门禁和小范围真实使用，再用实际数据决定 P1/P2 顺序。

如果首批目标租户已经把某些高级能力列为签约或上线硬条件，则选择 **选项 B**，但只勾选这些硬条件对应的阶段，不必为了“完成版”一次开发全部 18 个切片。

用户确认路线后，下一次只形成对应首个阶段的详细方案，不自动开始实施。
