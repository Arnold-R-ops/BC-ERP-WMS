## 审查中修正

扩展集成套件的采购确认和收货场景仍使用权限拆分前的模拟凭据，导致其准备步骤创建采购单时被后端正确拒绝为 403。测试已改为显式携带：

- 确认场景：`purchase:create + purchase:confirm`。
- 收货场景：`purchase:create + purchase:confirm + purchase:receive`。

修正后扩展集成回归 58/58 通过。该问题属于测试契约过期，不是生产鉴权绕过或业务接口缺陷。

根目录 `.gitignore` 已补充 `node_modules/`，避免依赖目录被误加入发布变更；该目录不再出现在 Git 未跟踪清单中。

## 发布门禁

功能验收通过，但正式发布尚未执行：

1. 当前分支为 `2-1G`，HEAD 为 `77dcfb4`，仍有 126 个已跟踪变更入口和 111 个未跟踪顶层入口。
2. 本机没有 Maven/Maven Wrapper；本轮已用独立 `javac + JUnit Platform` 验证当前源码，但正式发布制品仍应在具备 Maven 的 CI/构建环境执行 `mvn clean verify` 和 `mvn package`。
3. Flyway 9.22.3 对 PostgreSQL 18.1 的版本支持警告仍需单独升级计划。
4. 历史提交可能保留旧凭证；正式发布前仍需完成凭证轮换确认和历史扫描。
5. 未获得 Git 提交、推送或创建标签授权，因此不得宣称已经发布。
