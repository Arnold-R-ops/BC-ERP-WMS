# Codex 任务模型与推理强度规则

> 用途：每次开始新任务前先读取本文件，再选择模型和推理强度。目标是保证关键任务质量，同时避免所有任务都使用高成本配置。

## 一、开工顺序

1. 先读取本文件。
2. 再读取 `docs/CODEX_HANDOFF.md`，确认当前阶段、禁止修改边界和上一任务结果。
3. 根据下面的任务等级选择模型和推理强度。
4. 先限定本次任务范围，再开始读取文件或修改代码。
5. 任务完成后只报告：改了什么、验证结果、遗留问题、下一步。

## 二、任务等级与推荐配置

| 等级 | 适用任务 | 推荐模型 | 推理强度 |
|---|---|---|---|
| L0 | 解释概念、整理清单、改文档标题、简单翻译 | GPT-5.6 Luna | Low |
| L1 | 单文件文档、接口说明、简单样式或文字调整 | GPT-5.6 Luna | Low |
| L2 | 常规页面、单模块接口、局部 Bug、定向测试 | GPT-5.6 Terra | Medium |
| L3 | 跨 Controller/Service/Repository 的功能、前后端联调、回归测试 | GPT-5.6 Terra | Medium；必要时 High |
| L4 | 库存扣减、预占、并发、事务、权限、安全、Flyway、数据迁移 | GPT-5.6 Sol | High |
| L5 | 架构重构、生产发布、灾难恢复、租户隔离、关键数据修复、最终审查 | GPT-5.6 Sol | XHigh；必要时 Max |

## 三、本项目的直接套用规则

- 前端普通页面或单个交互：`Terra + Medium`。
- 前端视觉微调、文案、菜单改名：`Luna + Low`。
- 后端单接口或单模块修改：`Terra + Medium`。
- 出入库、库存预占、FEFO、整散分离、并发超卖：`Sol + High`。
- IAM、逻辑删除、权限边界、JWT、数据库迁移：`Sol + High`。
- 只读扫描接口与测试文件：`Terra + Medium`；只做文档分析时用 `Luna + Low`。
- 发布前、远程同步前、生产数据修复前：`Sol + XHigh`，并先输出方案和风险，不直接扩大范围。

## 四、推理强度的使用边界

- `Low`：问题明确、影响面小、失败容易回退。
- `Medium`：默认档，适用于大多数开发和测试任务。
- `High`：存在事务、并发、权限、库存、迁移或数据一致性风险。
- `XHigh`：多个模块互相影响，或需要正式发布前的完整审查。
- `Max`：只用于质量优先且失败代价很高的最终决策；不作为日常默认档。

模型选择不能替代验证。高推理强度仍必须通过编译、定向测试、接口验证或数据库检查证明结果。

## 五、节省流量和上下文的规则

- 一个任务只处理一个明确目标；架构讨论、代码开发、接口测试、验收尽量拆成不同任务。
- 开工先读交接文档和目标文件，不要默认扫描整个仓库。
- 测试优先运行受影响模块；只有明确要求或发布前才运行全量测试。
- 不重复粘贴完整日志、Token、响应文件和大段源码，只保留错误摘要与关键字段。
- 先查状态再行动：已有实现、已有迁移或已有测试时，不重复创建。
- 发现后端问题时记录“接口、输入、响应、推测原因、是否已复现”，不要无依据扩大修复范围。
- 涉及真实数据库、远程仓库、删除数据或生产配置时，先停在方案/确认阶段。

## 六、每次新任务可直接使用的启动提示词

```text
先读取 docs/CODEX_TASK_MODEL_POLICY.md 和 docs/CODEX_HANDOFF.md。
根据任务内容判断 L0-L5，先告诉我推荐模型、推理强度和本次范围。
遵守交接文档中的禁止修改边界；只处理本次目标，不扩大范围。
完成后报告修改文件、验证结果、已知问题和下一步，不输出无关长日志。
```

## 七、模型不可选时的替代规则

如果当前客户端没有显示上述模型名称：

- 复杂代码、库存、权限、迁移任务：选择当前可用的最高质量编码模型，并使用 High。
- 常规开发和联调：选择当前可用的平衡型模型，并使用 Medium。
- 文档和简单修改：选择当前可用的快速/经济型模型，并使用 Low。

以当前客户端实际可选项为准，不因为模型名称不同而改变任务边界和验证要求。
