## 已落实的建议

| 板块 | 本轮结果 | 保留的业务规则 |
|---|---|---|
| 采购与收货 | 整单默认仓带入商品，分仓按需展开；草稿允许分仓未完成；详情展示订、发、收进度，嵌入原收货表单 | 生效前完整分配检查；统一收货和库存记账 |
| 生产日期、有效期 | 发货预报可选；非效期商品新增批次不再无条件要求有效期 | 实际收货按商品规则核实；原审批、质检默认和可选能力保留 |
| 发货与物流 | 快递填写真实运单号；货运、自配送、自提不强制外部追踪号 | 实际出库扣实存，账单与收款不重复扣库存 |
| 整箱与零头 | 基础单位可设袋、瓶、盒；实存和可用量使用同一箱规，29 袋显示 2 箱 + 5 袋 | 沿用原包装换算 |
| 客户地址 | 默认收货地址与账单地址相同，可展开独立地址；前后端统一 255 字；订单可修改 | 保留权限和脱敏；报价保留当时地址，不随主资料修改 |
| 客户资料页 | 移除不可用预览占位，资料和编辑入口直接 | 没有新增“最近订单、常购商品、待办优先”首页 |
| 报价（新增） | 客户、商品、数量、价格、有效期、地址、条款；编辑、取消、转单；原报价保留已转单状态和销售单号，防止重复转单 | 报价不预留库存；转单调用原销售服务，继续执行审批、最低价和预留规则；直接销售不强制先报价 |
| 报价输出（新增） | 中文 PDF、公司抬头、跨页表头；XLSX 保留我方价格，空白客户意向单价和反馈备注 | 与报价共用快照；回传文件由业务员确认，不自动改订单 |
| 账单与收款（新增） | 已确认普通销售单开立商业账单；部分收款、待收余额、重试防重、超额拦截、追加冲正；未收款账单可作废 | 不连接银行；收款证据不覆盖；正式退货退款沿用原单 RMA |
| 低库存与补货 | 按仓阈值；净建议扣除可用量及有效采购未到量；选择商品带入原采购草稿 | 单仓兼容原阈值，多仓未配置明确显示；供应商、价格、数量可核对 |
| 报表与 CSV | 已确认订单额排除草稿、待审及无效单；销售汇总/每日、客户统计/常购商品、补货清单导出 CSV | 订单额不当作实收款；客户为累计，商品标明 Top 8；补货导出与页面同一筛选 |
| 退货 | 常用原因、中文类型；应退、已退、待退及下一步 | 只有成功退款回执计入已退；待检货不提前恢复可售 |
| 现有订单导入 | 内置 XLSX 用 SKU 编码，也接受条码，兼容旧 ID 模板；汇总错误行及可解析/错误/空行数 | 有错误整次拒绝，不部分落单；不新增通用主资料导入项目 |
| 权限与隔离 | 新报价/账单/收款/导出权限；已有租户迁移及新租户创建均登记；完整地址导出需独立权限 | 不自动授权普通岗位；保留客户归属、强制 RLS 和同租户外键 |

## 单独发现的原有平台问题

租户彻底清理函数 `bcwms_purge_company_data` 的外键依赖查询超过 100 秒未结束，已取消并回滚。排除本轮五张新增表后，原依赖查询仍超过 5 秒上限，见 `target/upgrade-baseline-purge-graph.log` 和 `target/check_baseline_purge_graph.sql`。

新增表按依赖删除、不可变收款及清理专用操作的兼容测试已通过；这不能替代整个平台彻底清理验收。本轮没有扩大范围重写平台。启用或执行租户彻底清理前应单独处理此问题；它不阻挡本次业务功能开发及隔离验收。
