# TENANT-ERP-P0-04C 多仓调拨闭环实施报告

- 交付状态：开发和自动化验证已完成；尚未合并、推送、部署或执行现有开发/生产数据库迁移。

## 1. 本阶段交付结果

P0-04C 已形成同一租户内两个不同仓库之间的完整调拨闭环：租户人员创建调拨单，系统按策略直接批准或进入审批，批准后预留来源仓可售库存并生成调出、调入两类仓库任务；仓库按批次调出形成在途库存，目的仓按库位分批调入，最终完成或受控关闭剩余差异。

本流程不复用采购、其他入库、销售发货或 RMA 入口。旧的直接库存调拨接口和 `inventory:transfer` 权限已经退役，所有库存变化都通过统一库存记账链路完成。

## 2. 单据、审批与三层状态

- 租户端新增 `/transfers` 调拨管理页面；仓库工作区新增 `/mobile/transfers`，按“调出任务 / 调入任务”分栏执行。
- 调拨单同时记录业务主状态、调出状态和调入状态，避免把批准、仓库发货和目的仓收货混成一条状态。
- 审批策略支持 `DIRECT`（默认直接批准）和 `ALWAYS`（始终审批），由租户自行配置，不与普通/高端套餐强绑定。
- `ALWAYS` 模式禁止制单人审批自己的调拨单；驳回后允许修改并重新提交，重新提交时清除上一轮审批结论。
- 只有草稿或已驳回单据可以修改核心业务字段；已形成库存事实后不允许改写历史，只能关闭剩余数量或创建反向调拨纠错。

## 3. 调拨分配、调出与在途库存

- 只分配来源仓 `AVAILABLE` 库存，支持指定批次或按 FEFO 自动分配；允许部分分配、重新分配和受控关闭未分配剩余。
- 调拨占用使用独立的调拨预留账本，不冒充销售预留；质量冻结、召回或处置时会扣除调拨预留后再判断可迁移的销售预留。
- 每次调出提交均为原子事务：任一行、批次、数量、版本、库位占用或库存条件不成立时，本次提交全部失败，不产生部分库存事实。
- 调出成功后释放相应调拨预留，来源仓实存减少，生成 `TRANSFER_OUT` 库存流水并进入在途；在途数量不计入任一仓的 ATP。
- 库存查询新增“在途数量”和“公司拥有数量”；公司拥有数量按“各仓实存 + 在途”展示，避免跨仓途中被误认为资产消失。

## 4. 调入、质检与差异关闭

- 目的仓收货必须选择实际库位；每条调入记录创建新的目的仓批次，同时保留来源批次链路，不直接搬用来源仓批次主键。
- 支持一张调拨单分批调出、分批调入和拆分到多个目的库位；累计调入不得超过已调出数量。
- 每次调入同样原子执行，并校验目的库位占用，禁止在不兼容库位中混放批次。
- 未开启质检时，合格调入库存直接进入 `AVAILABLE`；开启时进入 `PENDING_INSPECTION`，破损或隔离数量进入不可售状态并接入统一收货质检链路。
- 短少在明确关闭前继续保留为在途；错货不得落账，超收被禁止。差异关闭要求独立权限、原因、二次确认、最终调出证据和不可变审计，并保证不会再次扣减来源库存。

## 5. 销售欠货关联

- 调拨行可以选择关联一个目的仓销售欠货行；该能力不是必填，也不会把普通调拨变成销售流程。
- 关联后，批准调拨会把目标欠货置为等待调入；合格库存到达并进入 `AVAILABLE` 后，只定向唤醒对应欠货重新分配。
- 数据库只限制同时存在一个活动关联；已完成、关闭、取消或作废的历史调拨不会永久阻止同一欠货后续再次关联。

## 6. 权限、隐私、幂等与租户隔离

- 新增 `transfer:view`、`transfer:create`、`transfer:approve`、`transfer:dispatch`、`transfer:receive`、`transfer:close`、`transfer:policy` 七项独立权限。
- `transfer:view` 为 `NORMAL + 可分配`；其余六项为 `HIGH + 可分配`。普通用户默认不获得操作权限，租户管理员可以按岗位和仓库范围分配。
- 仓库任务 DTO 只展示 SKU、批次、数量、库位、优先级、预计时间段、作业人员/班组、作业区和仓库备注，不展示供应商、客户、成本、售价、承运商、运单、审批意见或销售欠货详情。
- 所有写操作要求 `Idempotency-Key`；前端幂等指纹包含资源 ID、最终版本和完整请求体，失败重试复用同一业务意图的键，不同任务不会误用同一键。
- 九张调拨表全部使用公司复合外键，并启用、强制执行 PostgreSQL RLS；出库、收货和事件证据使用不可变触发器保护。

## 9. 明确未纳入 P0-04C 的事项

- 不支持跨租户调拨、同仓库库位移动、跨公司所有权转移或调拨采购化。
- 不开发自动调拨建议、波次、托盘、路线、承运商、运单、标签或财务结算。
- 在途库存不进入 ATP，也不预先分配给销售订单；只有实际合格调入后才能参与销售分配。
- 不替代采购入库、销售发货、RMA 或仓内移动流程。
- 不执行真实手机/手持终端、扫码枪、标签打印机或面单打印机验收。
- 不执行合并、推送、部署或现有开发/生产数据库迁移。
