# 租户 ERP 会话安全：无感续期、1 小时空闲退出与全部会话撤销交接

更新日期：2026-08-19
文档状态：已实现、完成租户会话安全定向验证并启动最新租户本地运行态
适用范围：租户 ERP 前端与租户身份后端，不包含 `platform.bcwms.com` 平台管理员会话

## 1. 已确认目标

1. 租户 ERP 以“持续工作不中断”为正常体验目标，正常操作中的用户不能因为 JWT 固定到期而突然退出。
2. 连续 **1 小时无有效用户操作**时，租户 ERP 自动退出。
3. 用户被禁用、密码修改或重置、角色收回、相关角色权限被撤销，以及确认或怀疑会话泄露时，必须撤销该用户此前签发的全部租户 JWT。
4. 权限撤销优先于操作连续性：已经撤销的会话不得靠无感续期恢复。
5. 本任务不得修改平台管理员 JWT、平台 30 分钟空闲退出、平台 MFA 或平台 `sessionStorage`。
6. 本任务不得削弱 Host 与 `company_id` 匹配、租户 RLS、动态权限和 `security_version` 校验。

## 2. 当前实际基线

### 2.1 JWT 与浏览器会话

- 租户 JWT 与平台 JWT 已使用不同签名密钥、不同受众和不同主体类型，二者不能互换。
- 租户 JWT 当前有效期为 24 小时：`jwt.expiration = 86400000`。
- 租户和平台目前仍共用这一“时长配置”；本任务只处理租户 ERP 续期体验，不得顺带修改平台时长。
- 租户前端把 JWT 会话保存在 `localStorage` 的 `2g-wms.auth-session` 中。
- 前端保存 `expiresAt`，但当前没有 1 小时无操作计时器、到期前提示或完整的无感续期调用。
- 后端存在 `tenantTokenNeedsRefresh()` 和 1 小时 `refresh-threshold` 基础判断；权限白名单中也预留了 `/api/auth/refresh-token`，但当前没有完整 Controller、前端调用与端到端验收，不能视为已完成续期。
- 当前“退出登录”仅清除本浏览器保存的会话，不会主动撤销其他设备上的 JWT。

### 2.2 已有的立即失效能力

每个租户用户都有 `security_version`。JWT 内也保存签发时的版本。后端每次请求都会重新读取用户并比较版本、启用状态、用户名和 `company_id`。

当前以下操作已经推进 `security_version`，使旧 JWT 在下一次请求时被拒绝：

- 禁用或逻辑删除用户；
- 用户修改自己的密码；
- 租户管理员重置用户密码；
- 给用户新增、移除或整体替换角色；
- 修改角色状态、继承关系或角色权限，受影响用户同步失效；
- 用户切换当前角色时，旧 JWT 失效，并为新角色签发新 JWT。

这里的“立即”是指：数据库变更提交后，旧 JWT 的下一次后端请求立即收到拒绝。已经打开但没有发请求的静态页面不会被服务器主动推送关闭。

## 3. 本任务实施范围

### 3.1 连续 1 小时无操作自动退出

前端应建立租户 ERP 专用的空闲计时器：

- 空闲上限固定为 `60 * 60 * 1000` 毫秒；
- 不设置提前预警；用户已确认满 60 分钟后直接退出；
- 达到 60 分钟后清除租户会话并跳转登录页；
- 自动退出提示明确写“连续 1 小时无操作，已安全退出”；
- 多个租户 ERP 标签页之间应共享最近操作时间，任一 ERP 标签页的真实操作可保持同一浏览器会话；
- 任一标签页退出、被撤销或到期时，应同步通知其他 ERP 标签页退出；
- 自动刷新、轮询、后台定时请求、页面动画和单纯鼠标移动不得算作有效用户操作，避免无人值守页面永久续期；
- 建议计入的真实操作：键盘输入、点击/触控、表单提交、明确的页面导航和用户主动点击刷新。

空闲退出仅是前端体验和本机防护。它不能替代后端 JWT 到期或 `security_version` 撤销。

### 3.2 正常操作期间无感续期

建议沿用当前 24 小时租户 JWT 作为第一阶段基线，并完成已预留的续期能力：

- 只允许尚未过期、主体为 `TENANT`、Host/租户匹配且 `security_version` 仍有效的 JWT 请求续期；
- 仅当 JWT 剩余时间进入后端配置阈值时签发新 JWT，避免每个请求都换令牌；
- 前端仅在最近 1 小时内有真实用户活动时尝试续期；空闲页面不得续期；
- 续期时重新读取用户启用状态、当前角色、角色分配和权限上下文；
- 续期成功后原子替换本地 JWT 和 `expiresAt`，并同步其他 ERP 标签页；
- 续期失败或返回 401 时立即退出，不循环重试；
- 续期不能改变租户、用户或当前角色，不能让已撤销权限重新出现；
- 续期接口不得返回密码、数据库信息或其他会话的 JWT。

持续活跃用户的绝对最长登录周期已确认为 7 天。首次成功登录时间是周期起点；续期与切换角色都必须保留该起点。新 JWT 到期时间取“签发时间加 24 小时”和“首次登录时间加 7 天”中的较早者。达到 7 天后必须重新输入密码登录。

### 3.3 明确的“撤销全部会话”能力

建议第一阶段使用已有 `security_version` 实现“全部会话撤销”，不新建复杂设备会话表：

- 当前用户入口：`POST /api/auth/revoke-all-sessions`；
- 租户管理员撤销指定普通用户：建议 `POST /api/users/{userId}/revoke-sessions`；
- 两个接口均推进目标用户的 `security_version`；
- 当前用户自助撤销成功后，本标签页也立即退出；
- 管理员操作要求填写原因并通过确认弹窗二次确认；管理员不能撤销其他租户用户；`SECURITY_ADMIN` 对受保护身份继续遵守现有边界；
- 不允许用户绕过最后一个 `TENANT_ADMIN` 等既有保护规则；
- 操作必须写入租户安全审计，包含操作者、目标用户、原因、时间和结果，不记录 JWT；
- 疑似泄露时的推荐处置顺序：撤销全部会话 → 修改/重置密码 → 必要时禁用账号 → 调查审计。

由于当前 JWT 是无状态的，未建立设备会话登记表之前，只能可靠地“全部撤销”，不能准确列出或单独撤销某一台设备。若产品需要“设备列表、最后活跃、单设备退出”，应另立会话登记/刷新令牌任务，不能用伪造的设备列表交付。

### 3.4 禁用、改密和角色变化后的前端体验

- 后端继续以每次请求校验为最终边界；不能只靠前端隐藏功能。
- 前端收到 401 后清除租户会话并回到登录页。
- 建议区分用户可理解的稳定提示：会话到期、连续 1 小时无操作、账号或权限已变化、全部会话已撤销；不得向页面暴露内部异常、数据库结构或 JWT 校验细节。
- 用户自己修改密码成功后，明确提示“密码已修改，所有设备需要重新登录”，随后退出。
- 管理员重置他人密码后，目标用户旧 JWT 立即失效；目标用户使用临时密码登录后仍必须先修改密码。

## 4. 安全边界与非目标

- 不把租户 JWT 发送给平台域名、第三方服务、日志、URL 查询参数或错误详情。
- 不让已过期 JWT通过续期接口复活。
- 不因为前端仍有活动就跳过账号启用状态、角色或 `security_version` 校验。
- 不改变平台管理员的 30 分钟空闲退出和后续独立 8 小时 JWT 规划。
- 本任务暂不把租户 JWT 从 `localStorage` 迁移到 `HttpOnly` Cookie。该迁移涉及 CSRF、同源/跨域、子域、刷新令牌轮换和部署策略，应单独评审。
- 不实现“永久 JWT”或永不过期浏览器会话。
- 不让自动轮询、报表刷新或后台同步冒充用户活动。
- 不承诺全局保存所有未提交表单；满 60 分钟直接退出可能丢失尚未提交的数据。若要跨登录恢复草稿，需按数据敏感性为具体业务页面另行设计。

## 6. 必须补充的测试

### 后端

1. 有效且接近到期的租户 JWT 可以续期；未进入阈值时不重复签发或返回明确状态。
2. 已过期、错误签名、平台 JWT、Host/租户不匹配的 JWT 不能续期。
3. 用户禁用、密码变更、密码重置、角色收回或 `security_version` 不匹配后不能续期。
4. 续期后的 JWT 保持同一 `company_id`、用户和当前角色。
5. 自助和管理员撤销全部会话后，撤销前签发的 JWT 下一请求全部失败。
6. 租户 A 管理员不能撤销租户 B 用户会话。
7. 审计中不出现 JWT、密码或其他秘密。

### 前端

1. 59 分 59 秒仍保持会话，达到 60 分钟自动退出。
2. 60 分钟前不显示预警；达到 60 分钟直接退出。
3. 键盘、点击、触控和主动导航计入活动；轮询和鼠标移动不计入。
4. 活跃且接近 JWT 到期时只发起一次续期，成功后更新会话。
5. 空闲页面不续期；续期 401 后立即退出且不重试循环。
6. 一个标签页退出或被撤销时，其他 ERP 标签页同步退出。
7. 平台 `2g-wms.platform-auth-session` 不被读取、覆盖或清除。
8. 租户 ERP 原有登录、切换角色、修改密码、强制改密和权限错误处理不回归。

## 7. 手工验收场景

1. 正常操作超过原 JWT 临界点，页面完成无感续期，正在填写的业务不被打断。
2. 停止操作到 59 分 59 秒仍保持登录；满 60 分钟直接退出。
3. 停止操作满 60 分钟自动退出，重新登录后才能继续。
4. 管理员禁用一个已登录用户，该用户下一次请求立即退出。
5. 管理员重置密码或收回角色，该用户旧标签页下一次请求立即退出。
6. 用户点击“退出所有设备”，当前及其他浏览器中的旧 JWT 都不能再访问。
7. 使用租户 JWT 请求平台 API、使用平台 JWT 请求租户续期接口，均被拒绝。

## 8. 已确认的实施决策

1. 持续活跃用户最长登录 7 天；续期不能重置首次登录时间。
2. 不采用第 55 分钟预警；连续 60 分钟没有有效用户操作时直接退出。
3. 用户自助“退出所有设备”必须再次输入当前密码；租户管理员撤销指定员工的全部会话时必须填写审计原因并在弹窗中二次确认。
4. 本阶段只实现“全部会话撤销”，不建立设备会话登记表。

已将租户会话安全能力整合为租户 ERP 独立页面“用户权限 → 安全管理”：所有已登录员工可查看 7 天最长登录、60 分钟空闲退出和单张租户令牌 24 小时上限，并可在再次输入当前密码后执行“退出所有设备”；当前角色为 `TENANT_ADMIN` 时，额外显示员工全部会话撤销、原因填写、目标与原因二次确认，以及本租户最近的会话安全审计记录。设备列表、单设备退出、可信设备和新设备提醒仍不属于首期范围。

## 11. 工作区注意事项

- 当前工作区包含大量未提交的多租户、IAM 和平台端改动；不得清理、重置或覆盖无关文件。
- 租户与平台 JWT 密钥、受众和会话存储必须继续隔离。
- 修改认证公共代码前必须同时验证租户 JWT 与平台 JWT 分流，防止再次出现平台 JWT 被当作租户 JWT 校验的问题。
- 本文记录开发边界与已确认实现；是否上线仍以部署和环境验收结果为准。

## 12. 2026-08-19 实施结果

- 租户 JWT 增加原始登录时间，并按 `min(签发时间 + 24 小时, 首次登录时间 + 7 天)` 设置到期时间；登录、会话交接、续期和角色切换保持同一绝对登录周期。
- 完成 `POST /api/auth/refresh-token`、`POST /api/auth/revoke-all-sessions` 与 `POST /api/users/{userId}/revoke-sessions`；租户 Host、主体类型、用户状态、角色和 `security_version` 仍逐请求校验。
- 新增 `V4_66__Tenant_Session_Security_Audit.sql` 租户会话撤销审计表及 RLS 策略；审计记录操作者、目标用户、原因、结果和时间，不记录密码或 JWT。
- 租户 ERP 前端完成连续 60 分钟无有效操作直接退出、真实操作识别、无感续期、失败不循环重试、跨标签页活动/退出/令牌同步，以及刷新与退出并发时不恢复已删除会话。
- 跨标签页策略已收紧：其他标签页若正停留在登录页，不会因某一标签页成功登录而自动进入 ERP；已登录标签页仍同步令牌更新、退出与会话失效。新增自动化覆盖，确保登录页不被跨标签页登录状态激活。
- 员工自助“退出所有设备”要求当前密码；管理员入口要求填写至少 5 个字符的原因并二次确认。
- 平台会话键、平台 JWT、平台 30 分钟空闲退出及平台 MFA 未修改。
- 验证结果：后端会话安全、密码日志脱敏和客户服务回归共 68 项通过；前端会话相关 8 项通过；此前前端全量 166 项通过；TypeScript 检查和生产构建通过。
