# BCWMS 平台租户管理中心第一阶段交接

> 创建日期：2026-08-21
> 适用代码库：`D:\ERP_WMS\BC warehouse\2G`
> 推荐模型：涉及跨租户权限与审计时使用 **Sol / High**；仅做已确定的前端布局可使用 **Terra / Medium**。
> 本文是下一对话的执行依据；若与现有代码或数据库迁移记录冲突，先停止修改并核对事实，不得扩大权限。

## 1. 本次目标

把目前嵌在“平台首页”底部的“租户数据浏览”，整理为一个清晰、独立、只读优先的“租户管理”板块。

第一阶段交付以下能力：

1. 平台顶部增加独立的“租户管理”入口。
2. 建立租户目录页，支持按名称或编码搜索、状态筛选和后端分页。
3. 点击租户后先显示租户概览，不自动读取租户业务数据。
4. 把现有“数据集读取与导出”迁入租户详情。
5. 保持现有跨租户授权、后端强制校验和不可变审计规则。
6. 修复租户列表、概览、数据表格宽度不统一，以及宽表导致整页横向滚动的问题。

这一阶段不是单纯的平台管理员账号目录，也不是租户 ERP 页面。它是 BCWMS 运营方查看客户租户状态及在获授权范围内读取/导出数据的控制台。

## 2. 已确认的产品决定

### 2.1 名词

- 平台导航与页面统一使用“租户”。
- 首次说明写为“租户（客户公司）”。
- 这里的“公司”不是 BCWMS 自身运营主体，而是购买或使用 BCWMS 服务的客户公司。
- 后端实体、数据库字段及现有接口可以继续使用 `companyId`、`company_id`、`/companies`，本阶段不做破坏性重命名。
- 租户 ERP 端继续使用现有 `companyId` 语义，无需修改。

### 2.2 访问与读取策略

- 用户登录平台首页时不预取租户目录；进入“租户管理”页后自动加载当前授权范围内的目录第一页。
- 自动加载目录不得默认选择任何租户，也不得自动请求租户概览或业务数据。
- 点击某个租户后只显示租户概览。
- 只有操作者主动选择数据集时，才读取该租户的具体记录。
- 切换租户时清除已选择的数据集、表格数据和导出任务状态，防止误把上一个租户的状态带入新租户。
- 目录审计按一次分页查询写一条汇总记录，不为列表中的每个租户分别写审计记录。
- 数据读取、创建导出、导出完成、下载继续分别记录审计。

### 2.3 权限边界

- `PLATFORM_SUPER_ADMIN` 当前可以跨租户读取和导出，但不能直接修改或删除租户业务数据。
- 普通平台管理员不能仅凭全局 `PLATFORM_TENANT_READ` 或 `PLATFORM_TENANT_EXPORT` 角色跨租户通行。
- 普通平台管理员必须存在未撤销、未过期且精确匹配以下信息的授权记录：
  - 目标管理员；
  - `READ` 或 `EXPORT` 能力；
  - 具体租户；
  - 具体数据集；
  - 生效时间与到期时间。
- 授权默认 30 天，最长 90 天，可在范围内指定具体时间。
- 前端隐藏只是用户体验，后端每次请求仍必须重新校验有效授权。
- 其他管理员不得自我授权；超级管理员也不能借委派功能为自己新增租户写入或删除能力。

### 2.4 暂不实施

第一阶段不开发：

- 暂停、恢复、关闭、删除或清除租户；
- 直接修改租户业务记录；
- 套餐、计费、发票、付款；
- 完整配额管理及自动扩缩容；
- 批量租户操作；
- 工单、公告、租户通知；
- 跨区域迁移、灾备切换；
- 平台密钥复杂轮换；
- 租户 ERP 登录或会话策略变更；
- 普通平台管理员邀请和账号启停（另属“平台管理员生命周期”任务）。

## 4. 第一阶段详细实施范围

### 4.1 独立导航与路由

在平台顶部导航新增“租户管理”，建议路由为：

```text
/tenants
```

由于当前平台使用 `HashRouter`，浏览器实际地址会类似：

```text
platform.html#/tenants
```

实施规则：

1. 在 `PlatformProtectedRoute` 增加 `tenants` 视图。
2. 增加独立 `PlatformTenantManagementPage`（名称可调整，但职责必须独立）。
3. 从 `PlatformHome` 移除直接嵌入的 `TenantBrowser`。
4. 平台首页可以保留“当前有效租户能力”摘要，并提供前往“租户管理”的按钮。
5. 将首页中“租户数据浏览与导出流程将在后续任务中单独交付”的过期文案删除或改为实际入口说明。
6. 没有任何有效租户授权的普通管理员不显示“租户管理”导航；即使手工输入路由也由路由守卫和后端共同拒绝。
7. 超级管理员始终可以看到“租户管理”。

### 4.2 租户目录

页面左侧或上方提供目录控制区：

- 进入页面自动加载目录第一页；
- 关键词：匹配租户名称或租户编码；
- 状态：全部、`ACTIVE`、`SUSPENDED`、`CLOSED`（以实际枚举为准，不得伪造不存在的状态）；
- 创建时间范围（若本阶段实现成本合理）；
- “查询”与“重置”按钮；
- 后端分页，默认每页 20 条；
- 明确显示总数、当前页和加载/空/失败状态。

查询行为：

- 不应在每次键盘输入时立即请求后端。
- 初次进入页面、点击“查询”、翻页或显式重试时发起目录请求。
- 翻页请求继续保持当前筛选条件。
- 修改筛选条件但未点击“查询”时，不清空当前结果。
- 新查询从第 1 页开始。
- 普通管理员的搜索范围只能在其有效授权租户集合内。

建议扩展现有接口，而不是新建重复目录接口：

```http
GET /api/platform/companies?keyword=&status=&createdFrom=&createdTo=&page=0&size=20
```

后端要求：

- 参数必须类型校验和边界限制；
- `size` 仍受 `PlatformAccessProperties.maxPageSize` 限制；
- 使用数据库分页与条件查询，超级管理员不得先 `findAll()` 再在内存中过滤；
- 普通管理员可基于授权租户 ID 集合查询，但必须评估 ID 数量较大时的 SQL 方案；
- 防止 N+1 查询；
- 目录审计摘要中加入安全的筛选信息，但不要记录 JWT、密码、MFA、完整请求头或敏感查询内容。

### 4.3 租户详情：先概览，后数据

点击租户后，右侧默认只展示“租户概览”，不得自动选择 `users`，也不得自动调用任何 `/data/{resource}` 接口。

首版概览只展示平台控制面已持有的安全元数据：

- 租户名称；
- 租户编码；
- 状态；
- 创建时间；
- 关闭时间（存在时）；
- 计划清除时间（存在时）；
- 租户标识/域标识仅在确有运营价值时显示，避免暴露内部实现细节。

可增加“使用情况摘要”，但必须遵守：

1. 它是聚合数量，不展示原始业务记录。
2. 只有点击租户后才读取。
3. 不允许为生成概览扫描大表或逐项读取所有记录。
4. 只实现有可靠索引或现成高效计数的项目，例如启用用户数、仓库数、产品数。
5. 缺少高效查询时显示“暂未统计”，把指标进入后续队列；不得为了界面好看返回假数据。
6. 如果增加新概览接口，建议使用：

```http
GET /api/platform/companies/{companyId}/overview
```

7. 概览接口必须使用 `guard.requireTenantListed(companyId)` 或更严格规则，并写一条租户概览审计。

### 4.4 租户详情页结构

推荐首版仅设两个标签页：

1. “概览”
2. “数据浏览”

“数据浏览”复用现有 `TenantBrowser` 的数据集、表格和导出逻辑，但组件应拆分职责，避免租户目录在详情组件内重复维护。

推荐组件边界：

```text
PlatformTenantManagementPage
├─ TenantDirectoryFilters
├─ TenantDirectoryList
└─ TenantDetail
   ├─ TenantOverview
   └─ TenantDatasetBrowser
```

不要求照搬名称，但必须做到：目录查询状态、当前租户状态、数据集状态分离，切换租户时能可靠清除后两者。

### 4.5 数据集读取与导出

必须保留以下交互：

- 进入详情时数据集为空。
- 显式选择一个数据集后才发起读取。
- 仅读授权：显示数据表格，不显示导出按钮。
- 仅导出授权：显示导出能力，但不读取或显示表格。
- 读取和导出同时授权：两者都显示。
- 零有效授权：不显示租户入口；后端仍返回拒绝。
- 超级管理员：显示读取和导出，但不出现写入、编辑或删除按钮。
- 导出前必须再次展示当前租户与数据集供确认。
- 下载继续使用短期有效的 ZIP 导出结果和现有审计流程。

### 4.6 布局修复

用户已确认当前“左侧列表 → 右侧概览 → 数据集表格”宽度不一致，宽表会让整页出现横向滚动。

本阶段一并修复：

- 页面内容设合理最大宽度并居中或使用一致的全宽栅格；
- 左侧目录使用稳定宽度，右侧占剩余空间；
- 租户概览和数据集卡片使用同一右侧容器宽度；
- 表格横向滚动只能发生在表格容器内部，不能撑宽整个页面；
- 数据集选择器和导出按钮在窄窗口换行，不被裁切；
- 小屏幕时目录与详情改为上下排列；
- 加载前、加载后、选择租户后、选择数据集后的整体宽度不能跳变；
- 中英文切换均需检查。

布局调整不得改变“目录可自动加载、租户与数据集必须手动选择”的访问策略。

## 5. 安全与审计硬要求

### 5.1 身份边界

- 平台 JWT 只能由平台安全链校验，不得按租户 JWT 解析。
- 平台请求不得读取租户端 `localStorage` 会话。
- 平台 JWT 继续使用独立 `sessionStorage` 键。
- 平台账号不属于任何租户，不进入租户成员、角色、席位或租户审计。
- 所有租户上下文必须由后端根据已校验的目标租户建立，不能相信前端自行声明的公司或租户范围。

### 5.2 后端是最终裁决者

每个目录、概览、数据集、导出和下载请求都要在后端执行相应 guard：

- 目录：`requireTenantDirectory()`
- 单租户概览：`requireTenantListed(companyId)` 或更严格权限
- 数据读取：`requireRead(companyId, resource)`
- 导出和下载：对应的精确导出授权校验

不得把前端 `effectiveDatasetAccess()` 当成安全控制。

### 5.3 审计

至少保留或新增以下审计语义：

- 租户目录分页查询：一次请求一条汇总；
- 单租户概览查看；
- 数据集读取成功与失败；
- 导出创建、完成或失败；
- 导出下载成功与失败；
- 无权限尝试（由现有安全审计机制记录时，避免重复写两份含义相同日志）。

审计不得包含：

- JWT 或刷新令牌；
- `Authorization` 请求头；
- 密码；
- TOTP/MFA 密钥；
- MFA 验证码；
- 恢复码；
- 邀请原始令牌；
- 完整导出文件内容。

审计日志必须继续保持平台内部不可变，不提供普通页面删除或修改功能。

## 6. 正式上线前的服务器安全配置

本节是上线门槛，不要求全部在第一阶段本地页面开发中完成，但必须进入部署清单。

### 6.1 域名与网络

- 当前入口 `platform.bcwms.com` 仍是暂定值；正式上线前必须替换为最终域名并更新允许来源。
- 仅开放 HTTPS，HTTP 强制跳转 HTTPS。
- TLS 证书自动续期，禁用过时协议和弱密码套件。
- 平台管理域名可与租户 ERP 域名逻辑隔离；反向代理只暴露必要的平台前端与 `/api/platform/**`。
- 数据库、Redis、对象存储和管理端口不得直接暴露公网。
- 防火墙、云安全组和反向代理三层均按最小端口开放。
- 如有固定运营办公网络，可在不影响应急账号的前提下增加平台域名 IP/VPN 访问层；上线前单独确认。

### 6.2 应用配置与秘密

“秘密”是服务器必须保存但绝不能写进 Git、前端包或普通日志的敏感值，例如：

- 平台 JWT 签名密钥或私钥；
- MFA 数据加密主密钥；
- 数据库密码；
- SMTP/API 凭据；
- 对象存储访问密钥；
- 邀请令牌的服务端签名/散列相关密钥。

上线要求：

- 使用云密钥管理、Secret Manager、受限环境变量或权限严格的部署秘密文件；
- 不把秘密写入 `application.yml`、前端 `.env`、Docker 镜像层、交接文档或 CI 日志；
- 按运行身份授予最小读取权限；
- 开发、测试、生产使用不同秘密；
- 生产数据库账号按应用所需最小权限创建；
- 建立备份、恢复演练和秘密泄露后的替换方案；复杂自动轮换可后置，但人工可执行的应急轮换步骤不能缺失。

### 6.3 会话与浏览器安全

- 平台 JWT 最长 12 小时，连续 30 分钟无操作退出。
- “退出所有设备”继续要求当前密码流程定义所需的 MFA 再验证，并立即撤销全部平台会话。
- 响应设置合理的 CSP、HSTS、`X-Content-Type-Options`、Referrer Policy 和 frame 限制。
- CORS 只允许最终平台域名，不允许生产环境通配符。
- 登录、MFA、邀请、导出接口设置速率限制和异常告警。
- JWT、密码、MFA、恢复码和邀请令牌完成日志脱敏后才允许上线。

### 6.4 运营与可恢复性

- 生产至少保留两名独立、启用且完成 MFA 的 `PLATFORM_SUPER_ADMIN`，不共用认证器或恢复码。
- 恢复码离线分别保管，禁止发送到普通聊天群或写进代码库。
- 审计日志设置保留周期、只追加访问权限和异地备份。
- 数据库备份需验证可恢复，不以“备份任务成功”代替恢复演练。
