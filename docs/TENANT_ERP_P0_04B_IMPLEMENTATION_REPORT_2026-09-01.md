## 1. 本阶段交付结果

P0-04B 已形成从原销售发货证据到 RMA、退货收货、质检、退款或换货的闭环。正式 RMA 必须关联原销售订单、订单行、已完成出库任务和原出库批次，不提供无订单退货入口，也没有遗留 `rma:unlinked:create` 权限或接口。

租户端新增独立的“销售退货”页面，用于创建、审批、策略配置、商业处理和渠道退款待办；仓库端新增与统一收货相同形态的独立退货作业页面，仅展示执行收货和质检所需字段，不向仓库人员暴露客户、退货原因、承运商或运单号等商业信息。

## 2. RMA 类型与业务流转

- 支持 `RETURN_REFUND`（退货退款）和 `EXCHANGE`（换货）。
- `REFUND_ONLY`（仅退款不退货）由租户策略独立开启，默认关闭。
- 不开发维修、保修和无原销售证据的退货。
- 可申请数量受数据库证据约束：同一原出库明细累计有效 RMA 数量不得超过已发货数量。
- 商业退货期默认 5 天，可由租户配置；法定退货场景不会被商业天数硬性拦截，并保留适用依据、客户类型和策略快照。
- 审批模式为租户可选的 `DIRECT`、`RISK_BASED`、`ALWAYS`，默认 `DIRECT`，与租户套餐解耦。
- 授权后系统生成统一仓库退货任务；未发生收货时可取消，发生部分收货后只能关闭剩余数量，已收货事实不回退。

## 3. 仓库收货与质检

- 仓库操作人由登录账号识别，客户端不能提交或伪造操作人。
- 收货以 RMA 授权数量和原出库证据为上限，所有库存落账通过统一库存链路执行。
- 每次收货创建新的 `RETURN_INSPECTION` 退货批次和 `RETURN_IN` 库存流水，绝不把数量直接写回原出库批次。
- 质检按数量分配为 `AVAILABLE`、`DAMAGED`、`QUARANTINE` 或 `REJECT_CUSTOMER`，不使用 AQL 自动判定。
- 仓库质量处置与退款资格相互独立；商品质量差不等于客户一定无退款资格，商业责任由租户端处理。
- 可选隔离暂存策略默认关闭；本阶段不包含照片、附件、标签、打印机或真实设备功能。

## 4. 退款、换货与渠道事件

- 退款处理先写入领域 Outbox，等待外部支付或人工执行；人工确认时必须提供与请求完全一致的金额、币种和外部参考号，失败状态和原因保留，不能伪装为成功。
- 提前退款或换货默认关闭，同时要求租户策略开关、独立 `rma:advance-resolution` 权限和操作原因。
- 换货生成标准销售订单，标记为 `EXCHANGE_REPLACEMENT` 并关联来源 RMA；后续沿用正常分配、仓库和发货流程，但从新增销售收入汇总中排除。
- Shopify 等渠道退款 Webhook 仅形成原始事件及 `UNMATCHED_PENDING`/`MATCHED_PENDING` 审核队列，不直接改变库存或退款。
- 只有匹配原销售订单的渠道待办才能由租户人员人工建立正式关联 RMA；未匹配事件继续保留待处理证据。

## 5. 幂等、权限、审计与租户隔离

- 所有关键写操作要求 `Idempotency-Key`，同一租户内重放返回原业务结果，避免重复收货、质检、退款或换货。
- 新增 `rma:view`、`rma:create`、`rma:approve`、`rma:receive`、`rma:inspect`、`rma:resolve`、`rma:policy`、`rma:advance-resolution` 八项独立权限。
- `rma:view` 为 `NORMAL + 可分配`，其余七项为 `HIGH + 可分配`；权限可由租户管理员独立控制，普通用户不会因套餐自动获得高风险能力。
- 收货、质检和事件证据采用追加式保护，关键操作保留登录人、时间、原因和关联证据。
- 九张 RMA/渠道表均使用公司复合外键并启用、强制执行 PostgreSQL RLS，防止跨租户读取或关联。

## 6. 前端、接口与数据库

- 租户主页面新增 `/rmas`，包含 RMA 列表、创建、审批、关闭剩余、退款资格、退款/换货处理、人工退款确认、策略设置和渠道退款队列。
- 仓库工作区新增 `/mobile/rma`，只提供待收货任务、退货收货和逐数量质检。
- 新增租户 API `/api/rmas/**` 和仓库 API `/api/rma-warehouse/tasks/**`；未提供无订单退货路径。
- 新增迁移 `V4_83__Sales_Return_RMA_Closed_Loop.sql`，包含 RMA、行、任务、收货、质检、事件和渠道待办等九张表，以及约束、索引、RLS、不可变触发器、默认策略和权限目录。
- 实时 OpenAPI 已同步到 `docs/frontend/openapi.json`，TypeScript 契约已重新生成到 `frontend/src/api/schema.d.ts`。
