# WMS 系统测试执行指南

## 📋 测试环境准备

### 1. 环境要求
- Java 17+
- Maven 3.8+
- PostgreSQL 14+ 或 H2 数据库（测试环境）
- IDE：IntelliJ IDEA / Eclipse / VS Code

### 2. 配置测试环境

#### 2.1 测试配置文件
**文件路径：** `src/test/resources/application-test.yml`

```yaml
spring:
  datasource:
    url: jdbc:h2:mem:testdb
    driver-class-name: org.h2.Driver
    username: sa
    password:
  jpa:
    hibernate:
      ddl-auto: create-drop
    show-sql: true
  flyway:
    enabled: true
    locations: classpath:db/migration
```

#### 2.2 测试安全配置
**文件路径：** `src/test/java/com/wms/system/config/TestSecurityConfig.java`

确保测试安全配置已正确设置，允许测试用户访问受保护的端点。

## 🚀 运行测试

### 方法一：使用 Maven 命令行

#### 1. 运行所有测试
```bash
mvn clean test
```

#### 2. 运行特定测试类
```bash
# 运行 MaskingUtils 单元测试
mvn test -Dtest=MaskingUtilsTest

# 运行 CustomerService 单元测试
mvn test -Dtest=CustomerServiceTest

# 运行 CustomerController 单元测试
mvn test -Dtest=CustomerControllerUnitTest

# 运行 CustomerController 集成测试
mvn test -Dtest=CustomerControllerIntegrationTest

# 运行完整模块集成测试
mvn test -Dtest=CompleteModuleIntegrationTest

# 运行 API 接口测试套件
mvn test -Dtest=ApiEndpointTestSuite
```

#### 3. 运行特定测试方法
```bash
# 运行 MaskingUtils 的姓名脱敏测试
mvn test -Dtest=MaskingUtilsTest#testMaskName_TwoCharacters

# 运行 CustomerService 的行级隔离测试
mvn test -Dtest=CustomerServiceTest#testListCustomers_SalesRole_OnlyOwnCustomers
```

#### 4. 运行测试并生成报告
```bash
mvn clean test surefire-report:report
```

报告位置：`target/site/surefire-report.html`

#### 5. 运行测试并生成覆盖率报告
```bash
mvn clean test jacoco:report
```

覆盖率报告位置：`target/site/jacoco/index.html`

### 方法二：使用 IDE

#### IntelliJ IDEA

1. **运行所有测试**
   - 右键点击 `src/test/java` 目录
   - 选择 "Run 'All Tests'"

2. **运行单个测试类**
   - 打开测试类文件
   - 点击类名旁边的绿色运行按钮
   - 或右键点击类名，选择 "Run 'ClassName'"

3. **运行单个测试方法**
   - 打开测试类文件
   - 点击测试方法旁边的绿色运行按钮
   - 或右键点击方法名，选择 "Run 'methodName'"

4. **查看测试覆盖率**
   - 右键点击测试类或目录
   - 选择 "Run 'Tests' with Coverage"
   - 查看覆盖率报告

#### Eclipse

1. **运行所有测试**
   - 右键点击项目
   - 选择 "Run As" → "JUnit Test"

2. **运行单个测试类**
   - 右键点击测试类文件
   - 选择 "Run As" → "JUnit Test"

3. **运行单个测试方法**
   - 右键点击测试方法
   - 选择 "Run As" → "JUnit Test"

## 🐛 测试失败处理

### 1. 常见失败原因

#### 数据库连接失败
**错误信息：**
```
java.sql.SQLException: Connection refused
```

**解决方案：**
- 检查数据库是否启动
- 检查 `application-test.yml` 配置
- 使用 H2 内存数据库进行测试

#### 权限不足
**错误信息：**
```
org.springframework.security.access.AccessDeniedException: Access is denied
```

**解决方案：**
- 检查 `@WithMockUser` 注解的权限配置
- 检查 `TestSecurityConfig` 配置

#### 数据不一致
**错误信息：**
```
org.opentest4j.AssertionFailedError: expected: <张*> but was: <张三>
```

**解决方案：**
- 检查数据脱敏逻辑
- 检查角色权限判断
- 检查 Mock 对象配置

### 2. 调试测试

#### 启用详细日志
在 `application-test.yml` 中添加：
```yaml
logging:
  level:
    com.wms.system: DEBUG
    org.springframework.security: DEBUG
    org.hibernate.SQL: DEBUG
```

#### 使用断点调试
1. 在测试方法中设置断点
2. 右键点击测试方法
3. 选择 "Debug 'methodName'"

#### 查看 SQL 语句
在 `application-test.yml` 中启用：
```yaml
spring:
  jpa:
    show-sql: true
    properties:
      hibernate:
        format_sql: true
```

## 📝 测试最佳实践

### 1. 测试命名规范
- 单元测试：`ClassNameTest.java`
- 集成测试：`ClassNameIntegrationTest.java`
- API 测试：`ApiEndpointTestSuite.java`

### 2. 测试方法命名
```java
@Test
@DisplayName("测试场景描述")
void test<功能>_<场景>_<预期结果>() {
    // Given - 准备测试数据
    // When - 执行测试操作
    // Then - 验证测试结果
}
```

### 3. 测试数据管理
- 使用 `@BeforeEach` 准备测试数据
- 使用 `@AfterEach` 清理测试数据
- 使用 `@Transactional` 自动回滚

### 4. 测试隔离
- 每个测试方法独立运行
- 不依赖其他测试的执行顺序
- 使用 `@TestMethodOrder` 控制执行顺序（如需要）

### 5. 断言使用
```java
// 使用 AssertJ 进行流畅断言
assertThat(result).isNotNull();
assertThat(result.getName()).isEqualTo("张*");
assertThat(result.getPhone()).isEqualTo("139****5678");

// 使用 JUnit 断言
assertEquals("张*", result.getName());
assertTrue(result.getIsActive());
assertThrows(BusinessException.class, () -> service.method());
```

## 🔧 持续集成

### CI/CD 配置示例

#### GitHub Actions
```yaml
name: Run Tests

on: [push, pull_request]

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v2
      - name: Set up JDK 17
        uses: actions/setup-java@v2
        with:
          java-version: '17'
      - name: Run tests
        run: mvn clean test
      - name: Generate coverage report
        run: mvn jacoco:report
      - name: Upload coverage to Codecov
        uses: codecov/codecov-action@v2
```

#### Jenkins Pipeline
```groovy
pipeline {
    agent any
    stages {
        stage('Test') {
            steps {
                sh 'mvn clean test'
            }
        }
        stage('Coverage') {
            steps {
                sh 'mvn jacoco:report'
                publishHTML([
                    reportDir: 'target/site/jacoco',
                    reportFiles: 'index.html',
                    reportName: 'JaCoCo Coverage Report'
                ])
            }
        }
    }
}
```
