### 2. 数据脱敏工具类

**文件：** `MaskingUtils.java`

实现了以下静态方法：

#### 2.1 姓名脱敏 - `maskName(String name)`
- 保留第一个字，其余用 `*` 替换
- 示例：`"张三"` → `"张*"`

#### 2.2 手机号脱敏 - `maskPhone(String phone)`
- 保留前3位和后4位，中间用 `****` 替换
- 示例：`"13912345678"` → `"139****5678"`

#### 2.3 邮箱脱敏 - `maskEmail(String email)`
- 保留首字符和 `@` 后的域名
- 示例：`"john@gmail.com"` → `"j***@gmail.com"`

#### 2.4 地址脱敏 - `maskAddress(String address)`
- 保留前9个字符（省市区信息），隐藏详细街道/门牌
- 示例：`"北京市朝阳区建国路88号"` → `"北京市朝阳区***"`

#### 2.5 掩码检测 - `isMasked(String value)`
- 检查字符串是否包含掩码字符
- 用于修改保护逻辑

**技术特性：**
- 空值安全，避免 NullPointerException
- 支持各种边界情况（空字符串、短字符串等）
- 静态方法，无需实例化

### 5. Service 层核心逻辑

**文件：** `CustomerService.java`

#### 5.1 行级隔离（Row-Level Security）

**实现位置：**
- `listCustomers()` - 查询所有客户
- `listActiveCustomers()` - 查询激活客户

**业务逻辑：**
```java
if (isSalesRole() && !isManagerOrAdmin()) {
    // 销售员只能查看自己的客户
    Long currentUserId = getCurrentUserId();
    customers = customerRepository.findByOwnerId(currentUserId);
} else {
    // 管理员和经理可以查看所有客户
    customers = customerRepository.findAll();
}
```

**角色判断：**
- **SALES 角色：** 只能查看 `owner_id = currentUserId` 的客户
- **ADMIN/MANAGER 角色：** 可以查看所有客户

---

#### 5.2 动态脱敏（Dynamic Masking）

**实现位置：**
- `convertToResponse(Customer customer, boolean shouldMask)` - DTO 转换方法
- 所有返回 `CustomerResponse` 的方法

**脱敏逻辑：**
```java
boolean shouldMask = isSalesRole() && !isManagerOrAdmin();

if (shouldMask) {
    return CustomerResponse.builder()
        .name(MaskingUtils.maskName(customer.getName()))
        .phone(MaskingUtils.maskPhone(customer.getPhone()))
        .email(MaskingUtils.maskEmail(customer.getEmail()))
        .address(MaskingUtils.maskAddress(customer.getAddress()))
        // ... 其他字段
        .build();
}
```

**脱敏字段：**
- `name` - 姓名脱敏
- `phone` - 手机号脱敏
- `email` - 邮箱脱敏
- `address` - 地址脱敏

**不脱敏字段：**
- `id`, `code`, `contact`, `creditLimit`, `isActive`, `createdAt`, `updatedAt`

---

#### 5.3 修改保护（Edit Protection）

**实现位置：**
- `updateCustomer(Long id, CreateCustomerRequest request)` - 更新客户方法

**保护逻辑：**
```java
// 如果字段包含掩码，忽略更新
if (!MaskingUtils.isMasked(request.getPhone())) {
    customer.setPhone(request.getPhone());
} else {
    log.debug("Phone contains mask, skipping update");
}
```

**保护字段：**
- `phone` - 手机号
- `email` - 邮箱
- `address` - 地址

**业务场景：**
- 销售员查看客户时，敏感字段被脱敏
- 销售员提交修改表单时，如果字段包含 `****`，后端忽略该字段的更新
- 保持数据库原值不变，防止脱敏数据覆盖原始数据

---

#### 5.4 自动设置归属人

**实现位置：**
- `createCustomer(CreateCustomerRequest request)` - 创建客户方法

**业务逻辑：**
```java
// 获取当前登录用户ID
Long currentUserId = getCurrentUserId();

// 创建客户实体
Customer customer = Customer.builder()
    // ... 其他字段
    .ownerId(currentUserId)  // 自动设置归属人
    .build();
```

**说明：**
- 创建客户时，自动将 `owner_id` 设置为当前登录用户
- 销售员创建的客户归属于自己
- 管理员创建的客户也会记录创建人

---

#### 5.5 辅助方法

**实现的辅助方法：**

1. **`getCurrentUserId()`** - 获取当前登录用户ID
   ```java
   Authentication authentication = SecurityContextHolder.getContext().getAuthentication();
   SecurityUser securityUser = (SecurityUser) authentication.getPrincipal();
   return securityUser.getId();
   ```

2. **`isSalesRole()`** - 判断是否为销售角色
   ```java
   return authentication.getAuthorities().stream()
       .map(GrantedAuthority::getAuthority)
       .anyMatch(auth -> auth.equals("SALESPERSON") || auth.equals("SALES"));
   ```

3. **`isManagerOrAdmin()`** - 判断是否为管理员或经理
   ```java
   return authentication.getAuthorities().stream()
       .map(GrantedAuthority::getAuthority)
       .anyMatch(auth ->
           auth.equals("SUPER_ADMIN") ||
           auth.equals("WAREHOUSE_ADMIN") ||
           auth.equals("CHAIRMAN") ||
           auth.equals("MANAGER")
       );
   ```

#### 6.2 权限分配

- ✅ **WAREHOUSE_ADMIN** - 授予 `customer:export` 权限
- ✅ **CHAIRMAN** - 授予 `customer:export` 权限
- ✅ **SALESPERSON** - 禁止 `customer:export` 权限
- ✅ **STAFF** - 禁止 `customer:export` 权限

**SQL 示例：**
```sql
-- 添加权限
INSERT INTO sys_permissions (permission_code, permission_name, description, resource_type)
VALUES ('customer:export', '导出客户数据', '允许导出客户数据到Excel', 'OPERATION');

-- 为管理员授权
INSERT INTO sys_role_permission (role_id, permission_id)
SELECT r.id, p.id
FROM sys_roles r, sys_permissions p
WHERE r.role_code = 'SUPER_ADMIN' AND p.permission_code = 'customer:export';

-- 删除销售员的导出权限
DELETE FROM sys_role_permission
WHERE role_id IN (SELECT id FROM sys_roles WHERE role_code = 'SALESPERSON')
  AND permission_id IN (SELECT id FROM sys_permissions WHERE permission_code = 'customer:export');
```

## 🔒 安全特性总结

### 1. 行级隔离（Row-Level Security）
- 销售员只能查看和管理自己的客户（`owner_id = currentUserId`）
- 管理员和经理可以查看所有客户
- 数据库层面通过 `owner_id` 字段实现隔离

### 2. 动态脱敏（Dynamic Masking）
- 销售员查看客户时，敏感字段自动脱敏
- 管理员和经理查看原始数据
- 不修改数据库原始数据，只修改返回给前端的 DTO

### 3. 修改保护（Edit Protection）
- 销售员提交包含掩码的字段时，后端忽略更新
- 保持数据库原值不变
- 防止脱敏数据覆盖原始数据

### 4. 权限控制（Permission Control）
- `customer:export` 权限仅授予管理员和经理
- 销售员无法导出客户数据
- 防止批量数据泄露

## ⚠️ 注意事项

### 1. 数据库迁移
- 执行迁移前请备份数据库
- `owner_id` 字段允许为 NULL，现有客户数据不受影响
- 如需为现有客户分配归属人，请手动执行 UPDATE 语句

### 2. 性能优化
- `idx_customer_owner` 索引已创建，优化按归属人查询性能
- 大量客户数据时，建议添加分页查询

### 3. 权限配置
- 确保数据库中存在 `sys_roles` 和 `sys_permissions` 表
- 如果角色名称不同，请修改迁移脚本中的角色代码

### 4. 前端适配
- 前端需要处理脱敏数据的显示
- 提交表单时，如果字段被脱敏，建议不发送该字段或发送原值
