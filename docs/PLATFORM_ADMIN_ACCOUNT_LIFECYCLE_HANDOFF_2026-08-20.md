# 平台管理员账号生命周期交接方案

> 日期：2026-08-20
> 推荐执行模型：GPT-5.6 Sol / High
> 本文范围：平台管理员目录、账号启停、普通平台管理员邀请，以及正式上线前服务器安全配置。
> 明确延后：复杂 MFA 加密密钥轮换、SSO、Passkey、正式邮件投递和 break-glass 自动化。

## 一、已确认的实施顺序

下一阶段先实施：**平台管理员目录与账号启停安全底座**。

完成并验收后，再单独实施：**普通平台管理员邀请**。

这样安排的原因：

1. 在继续增加平台账号前，必须先能准确查看账号、角色、MFA 和启停状态。
2. 必须先具备安全停用账号、立即撤销会话和禁止自我停用／停用最后一名超级管理员的能力。
3. 普通管理员邀请依赖稳定的角色、账号状态和生命周期规则；先邀请、后补停用会留下不可控账号。
4. 当前页面的管理员列表复用了委派授权模块的 `/api/platform/access-grants/users`，下一阶段应改为独立管理员目录，避免账号管理继续与租户授权耦合。

## 二、“BCWMS 后端”“平台后端”和“租户 ERP 后端”的边界

当前工程是一个 Spring Boot 应用，但其中包含两个逻辑边界：

- **平台后端／控制面**：`src/main/java/com/wms/system/platform/**`，处理平台管理员登录、MFA、管理员邀请、审计、租户目录和委派授权。
- **租户 ERP 后端／业务面**：处理租户用户、仓库、商品、库存、订单和租户内部权限。

因此此前所说“BCWMS 后端保存 MFA 秘密”，准确说法应为：

> **BCWMS 服务中的平台后端模块保存平台管理员的 TOTP 共享秘密；租户 ERP 用户表和租户业务接口不参与平台 MFA。**

平台 MFA 数据只属于 `platform_users` 和平台 MFA 挑战表，不应写入租户用户、租户角色、租户席位或租户审计。

### “保存一份秘密”具体是什么

绑定认证器时，二维码中的 `otpauth://` 内容包含一段随机生成的 **TOTP 共享秘密（seed）**：

- 管理员手机认证器保存一份；
- 平台后端以 AES-GCM 加密后保存一份；
- 手机和平台后端分别用“共享秘密 + 当前时间”计算 6 位验证码；
- 两边计算结果一致，才通过 MFA。

这段共享秘密不是管理员密码、JWT、6 位动态码或恢复码。6 位动态码约每 30 秒变化；共享秘密长期不变，除非重置并重新绑定认证器。平台后端如果完全不保存它，就无法自行核对 TOTP；只有将 MFA 全部交给外部身份提供商时，平台后端才可以不保管该秘密。

## 三、当前已完成基线

- 当前本地数据库恰有 2 名启用的 `PLATFORM_SUPER_ADMIN`，两者均完成独立 MFA 绑定并各有 10 个未使用恢复码。
- 第二名超级管理员通过 24 小时、单次邀请链接完成强密码、MFA 和恢复码流程；`ADMIN_INVITATION_ACCEPTED` 审计为 `SUCCESS`。
- 超级管理员只具备平台侧永久读取／导出能力，不能因此直接修改或删除租户数据。
- 普通平台管理员即使具有 `PLATFORM_TENANT_READ`／`PLATFORM_TENANT_EXPORT` 候选角色，也必须同时存在精确到租户、数据集、能力和有效期的授权记录。
- 当前平台会话最长 12 小时，连续 30 分钟无操作退出；“退出所有设备”要求再次 TOTP。
- 平台 MFA 密钥轮换暂不开发。当前本地数据库继续作为开发验收环境，推荐正式上线使用全新生产数据库并在创建生产管理员前设置独立 MFA 加密密钥。

## 四、第一板块：独立管理员目录

### 4.1 后端范围

新增超级管理员专用的独立接口：

```text
GET /api/platform/admins
```

返回每名平台管理员的安全摘要：

- 平台用户 ID
- 邮箱
- 显示名称
- 启用／停用状态
- 角色代码列表
- MFA 状态：待绑定、已绑定、暂时锁定
- 创建时间、更新时间
- MFA 绑定时间（可为空）

首版不返回：

- 密码或密码散列
- MFA 共享秘密或加密密文
- 恢复码或恢复码散列
- JWT、会话令牌或 MFA 挑战令牌
- 邀请原始令牌
- 租户业务数据

现有 `/api/platform/access-grants/users` 继续只服务委派授权页面；管理员管理页迁移到新的 `/api/platform/admins`，不再把授权候选人接口当作账号目录。

### 4.2 前端范围

将“管理员管理”页面拆为两个清晰区域：

1. **管理员目录**：显示姓名、邮箱、角色、MFA、账号状态和安全操作。
2. **邀请记录**：保留超级管理员邀请历史；普通管理员邀请在第二板块开发。

目录支持刷新和安全的错误提示。首版不做搜索、批量操作、删除、导出或编辑邮箱。

## 五、第一板块：受控账号停用与恢复

### 5.1 推荐接口

```text
POST /api/platform/admins/{targetUserId}/status-change/challenge
POST /api/platform/admins/{targetUserId}/disable
POST /api/platform/admins/{targetUserId}/enable
```

最终启停请求必须包含：

- 5 分钟、单次、绑定操作者／目标账号／目标状态的挑战令牌
- 操作者当前密码
- 操作者认证器当前 6 位 TOTP
- 最长 500 字的必填原因

密钥、密码和 TOTP 不进入 URL、审计详情或日志。

### 5.2 强制安全规则

- 只有 `PLATFORM_SUPER_ADMIN` 可以启停平台管理员。
- 操作者不能停用自己。
- 不能停用最后一名启用的 `PLATFORM_SUPER_ADMIN`。
- 不能通过普通启停接口修改角色、重置 MFA 或删除账号。
- 停用成功后立即递增目标账号 `security_version`，使目标全部平台 JWT 失效。
- 停用成功后清理目标未完成的平台 MFA／再次验证挑战。
- 停用不删除角色、委派授权、MFA 绑定、恢复码、审计日志、导出任务或其他已持久化记录。
- 停用账号不能登录，也不能调用平台接口。
- 恢复启用不会恢复旧 JWT；目标必须重新用密码和 MFA 登录。
- 恢复启用后，尚未过期且未撤销的委派授权会重新生效；确认弹窗必须提醒操作者检查授权范围。
- 重复停用已停用账号或重复启用已启用账号应安全幂等，不产生重复状态变化。
- 并发操作必须再次核验“至少一名超级管理员仍启用”，不能只依赖前端按钮禁用。

### 5.3 审计动作

- `ADMIN_DISABLED`
- `ADMIN_ENABLED`
- 再次验证失败沿用安全失败审计，但不能泄露密码、TOTP、MFA 密钥或挑战令牌。

审计至少包含操作者、目标平台用户 ID、目标邮箱的安全快照、原因、操作前后状态、时间、结果、请求 ID 和来源 IP。审计不可修改、不可删除。

## 六、第二板块：普通平台管理员邀请

仅在独立管理员目录和启停功能验收通过后开始。

### 6.1 推荐首版角色范围

普通管理员邀请只允许以下受控组合：

- `PLATFORM_TENANT_READ`
- `PLATFORM_TENANT_EXPORT`
- `PLATFORM_TENANT_READ` + `PLATFORM_TENANT_EXPORT`

普通邀请不得分配：

- `PLATFORM_SUPER_ADMIN`（继续使用现有独立超级管理员邀请流程和最多两名规则）
- 任何直接写入或删除租户数据的角色
- 未在固定白名单中的角色

### 6.2 权限边界

- 普通管理员激活后默认没有任何具体租户授权。
- 只有角色没有授权记录时，不显示租户浏览／导出菜单，后端也拒绝对应请求。
- 只有超级管理员随后授予具体租户、数据集、READ／EXPORT 能力和有效期后，能力才生效。
- 其他管理员不能自我授权；超级管理员不能通过委派授权获得写入／删除能力。

### 6.3 激活流程

复用已验收的安全流程：24 小时、单次链接；受邀人设置强密码；立即绑定自己的 MFA；恢复码只显示一次；MFA 完成前不签发平台 JWT。首版仍由邀请人通过安全渠道人工发送链接，不接入邮件系统。

## 七、需要在新对话开始时再次确认的产品细节

建议默认采用以下规则：

1. 第一任务只交付“独立管理员目录 + 单账号启停”，不同时开发普通邀请。
2. 停用保留 MFA、角色和委派授权；恢复启用时提醒检查仍有效授权。
3. 启停必须要求操作者当前密码 + TOTP，恢复码不能替代该次再次验证。
4. 不提供账号删除、批量停用、邮箱修改或角色编辑。
5. 普通管理员邀请放在第二任务，角色只允许 READ／EXPORT 三种组合。
6. 正式上线采用全新生产数据库；当前本地演示租户和本地平台 MFA 数据不迁移。

如用户没有提出不同要求，按以上推荐规则实施。

## 八、第一板块验收清单

### 后端自动测试

- 非超级管理员不能读取管理员目录。
- 返回对象不包含密码、JWT、MFA 密钥、恢复码或挑战令牌。
- 不能停用自己。
- 不能停用最后一名启用的超级管理员。
- 能停用另一名管理员并立即使旧 JWT 失效。
- 停用会清理未完成挑战，但不删除持久化任务、角色、授权和审计。
- 恢复启用后旧 JWT 仍无效，重新登录成功。
- 重复启停幂等；并发停用不能绕过最后超级管理员保护。
- 启停成功和失败均有安全审计，日志不包含敏感输入。

### 前端自动测试

- 管理员页面改用 `/api/platform/admins`。
- 当前账号不显示“停用自己”。
- 最后一名超级管理员不显示可执行的停用操作。
- 确认弹窗展示影响范围并要求原因、密码和 TOTP。
- 操作成功刷新目录；再次验证失败保留当前登录会话并给出准确提示。
- 无权限时不显示管理员管理入口。

### 人工验收

使用两个本地超级管理员账号执行：

1. A 查看目录，确认两名账号均启用且 MFA 已绑定。
2. A 尝试选择自己，页面不得允许停用。
3. 不实际停用之前先确认 B 已保存恢复码并可独立登录。
4. 如用户明确批准，再由 A 停用 B；确认 B 的现有会话失效、任务和审计未丢失。
5. A 恢复启用 B；B 必须重新登录，但无需重新绑定 MFA。

第 4～5 步会改变真实本地账号状态，必须在执行前再次取得用户明确确认。

## 九、正式上线前服务器安全配置

以下属于上线门禁，不在普通前端页面中配置。

### 9.1 环境与数据库

- 使用全新的生产数据库，不迁移当前本地演示租户、测试管理员会话或本地 MFA 密文。
- 应用数据库账号不得是 `SUPERUSER`，不得具有 `BYPASSRLS`；按迁移账号和运行账号分权。
- 正式启用并验收租户隔离策略、双租户越权测试、备份恢复和保留期清理。
- 生产数据库不直接暴露公网；仅允许应用和受控运维网络访问。

### 9.2 独立秘密

- `PLATFORM_JWT_SECRET`：独立、随机、至少 256 位。
- `PLATFORM_MFA_ENCRYPTION_KEY`：与 JWT 完全不同、Base64 编码、至少 256 位，在创建首个生产平台管理员前设置。
- 数据库密码、SMTP 凭据和第三方集成密钥分别管理，不能复用。
- 秘密只进入受控秘密管理系统或部署环境，不写入 Git、Markdown、镜像、数据库迁移、日志或聊天。
- 复杂 MFA 密钥轮换功能暂不开发；上线前只要求首次密钥正确设置、备份和访问权限明确。

### 9.3 域名、网络与 TLS

- 正式入口使用 `https://platform.bcwms.com`，替换当前本机地址。
- 只通过受控反向代理暴露 443；Spring Boot 8080 不直接暴露公网。
- 配置有效 TLS 证书、HTTPS 强制跳转、HSTS 和安全响应头。
- 严格限制允许的 Host、Origin 和 CORS；不得相信任意公网 `X-Forwarded-Host`。
- 平台 JWT 不进入 URL、查询参数、日志或跨子域共享 Cookie。

### 9.4 时间与 MFA

- 服务器必须启用可靠 NTP 时间同步；TOTP 依赖准确时间，时钟漂移会导致正确验证码被拒绝。
- 生产节点时区可使用 UTC，但所有节点必须保持一致、可监控。
- 首个生产超级管理员建立后，再由其通过受控邀请创建第二名正式超级管理员；两人使用不同邮箱、密码、认证器设备和离线恢复码保管位置。

### 9.5 日志、审计与监控

- 生产使用 `prod` 配置，关闭 Spring Web／Hibernate SQL DEBUG 输出。
- 日志必须遮蔽密码、JWT、邀请令牌、MFA 共享秘密、恢复码和挑战令牌。
- 平台审计日志保持不可修改、不可删除，并设置异常登录、MFA 锁定、大量读取／导出和管理员状态变化告警。
- 日志保留、访问人员、导出审批和备份策略在上线清单中明确。

### 9.6 启动与账号初始化

- 旧租户单公司管理员 bootstrap 在生产保持关闭。
- 平台 bootstrap 只允许首次受控开户使用；首个账号完成后立即关闭并移除一次性输入。
- 不在部署脚本、命令历史或 CI 输出中打印初始密码、JWT 或 MFA 密钥。
- 启动时缺少独立 MFA 密钥、JWT 密钥或生产数据库安全条件应直接失败，不允许静默回退到开发默认值。

### 9.7 上线前恢复演练

- 验证两名超级管理员均可独立登录。
- 验证单账号停用、恢复和会话撤销不影响另一名超级管理员。
- 验证使用一枚恢复码登录后该码立即失效，其余恢复码仍有效。
- 验证数据库备份可恢复，恢复后平台审计、角色、授权和 MFA 状态一致。
- 验证正式域名、TLS、反向代理、限流、时钟同步和日志脱敏。

## 十、明确不在下一任务中的内容

- 不轮换当前 MFA 加密密钥。
- 不把本地数据库或本地 MFA 密文直接提升到生产。
- 不执行现有两名超级管理员的 MFA 重置。
- 不开发 SSO、SAML、OIDC、Passkey 或邮件自动发送。
- 不开发平台账号删除、租户数据写入／删除或全租户通配授权。
- 不修改租户 ERP 用户登录、租户 JWT、租户角色或租户业务数据。
