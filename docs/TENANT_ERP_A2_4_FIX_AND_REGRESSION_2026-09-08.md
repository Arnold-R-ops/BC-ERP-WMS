## 1. 业务修复

### B-01 销售取消和关闭未发余量

- 为尚未开始的出库任务增加统一的 `voidUnstarted` 操作，同时记录当前登录操作人的 ID、终止时间和完整原因。
- 沿用现有任务 `VOIDED` 状态及 `archived_*` 审计列，明确它们也记录业务任务终止；销售订单仍为业务 `CANCELLED` 或 `CLOSED`，不把正常业务取消伪装成历史测试数据清理。
- 保留 `ck_outbound_task_archive_fields` 原约束，不修改历史 Flyway 文件、不删除约束、不新增迁移。历史测试数据归档仍由受控服务和独立审计记录管理。
- 仅更新 PENDING 且未实际发货的任务；已经完成或此前终止的任务不覆盖原证据。已开始拣货/质量异常仍按现有保护规则先处理实物，不开放强行取消。
- 订单、未发数量、预留释放和任务终止维持同一事务；不通过取消操作扣减实存。
- 同一缺陷也存在于质量处置释放未开始任务至缺货单的路径，已接入相同审计方法，并补断言；没有增加新的质量处置入口或权限。

### B-02 盘点保存、更正与明确提交复核

- 单项计数保存不再自动把整单转为 REVIEWING。
- COUNTING 阶段，包括复核驳回后，允许重新扫码或点选已计数项进行更正；不清空其他已保存计数，不要求整仓重盘。
- 手机和电脑统一以“完成本次盘点”作为提交复核入口；未全部计数时禁用并由服务端再次验证。
- 手机当前修改尚未保存或请求正在进行时，不允许直接完成盘点；保存失败保留当前输入。离线禁止计数和完成写入。
- 重复 finish 在已经 REVIEWING 时幂等成功；进入复核后不能再提交计数。
- 保留原盲盘投影、计数/复核权限、复核命令幂等和差异记账规则；未改变谁有权复核。
- API 路径和 DTO 字段未变，本次无需重新生成 OpenAPI/TypeScript 接口类型。
