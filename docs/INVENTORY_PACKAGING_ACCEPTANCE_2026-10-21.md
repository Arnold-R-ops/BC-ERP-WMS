# 批次、库位、整箱与拆箱余量：本轮验收记录

日期：2026-10-21。分支：`codex/salesbinder-acceptance-20261004`，实施基线：`0627a0f`。

本轮按用户批准的范围实施：记录实物包装，加入整理与盘点，贯通相关出入库；不引入用户箱号，不新增导航模块或审批链。本次交付包含源码、数据库迁移、测试脚本与验收记录，提交版本以本分支 Git 记录为准。服务器尚未部署，原业务数据库未改动。

## 已实现的行为

| 操作 | 当前行为 |
| --- | --- |
| 库存查询 | 每个批次、库位记录未拆整箱数和各拆箱余量。拆箱数量按明细条数计算，基础数量仍是原库存账的余额。 |
| 历史库存核实 | 原数据保留数量，显示“包装未核实”。核实只能补充等量组成，不能通过补录增加库存。 |
| 整理、开箱、移位 | 在“库存查询 → 查看批次”勾选参与的批次/库位行，点击“整理 / 开箱 / 移位”，填写每个目标库位的未拆整箱与各拆箱数量。选择的是整条库位余额，表单带入其全部组成；未改变的余量保留在结果中。 |
| 合箱与拆分 | 9+8 可记为一个 17，也可记为 12+5；12 或 17 都仍是拆箱。箱规不限制整理后的实际余量。 |
| 整箱分散存放 | 同批次未拆整箱可分布在多个库位。移动时同步各库位库存及组成，不改变全仓总量。移出后可再移回原库位。 |
| 同库位整理 | 总量必须相等，只更新组成和操作记录，不产生损益流水。不能把拆箱自动变为未拆整箱。 |
| 跨库位整理 | 来源和目标同时记账，失败全部回滚。同仓、同商品、同批次且质量和日期相容才允许操作；已有目标库存须一并选入。 |
| 收货 | 可记录实际整箱和拆箱组成；未录入时保留“包装未核实”。同次收货中相同来源明细与批次/日期条件可分到不同库位。 |
| 拣货、出库 | 已核实库存需确认实际取货来源。取某个 9 袋拆箱的 4 袋后，该拆箱为 5 袋；另一个 8 袋拆箱不变。开一个 12 袋整箱并发 3 袋，留下 9 袋，仅扣 3 袋。 |
| 调拨 | 出库、在途、部分接收同步包装组成；避免拆分接收时重复使用同一份数量。跨仓继续沿用原调拨批次及来源追溯规则，没有重构批次体系。 |
| 盘点 | 复用原盘点入口，录入未拆整箱与各拆箱余量，自动合计实盘数。数量不变只更新组成；实际少 1 袋则沿用原差异处理并同步余量。原复核步骤保留。 |
| 作业保护 | 有预留或未完成拣货任务的库存不可整理/启动盘点；盘点中的库存禁止被整理、出库及质量转换。提交校验版本，旧页面不能覆盖新记录。 |

没有箱号时，系统保存的是当前库位上的各份余量，不承诺识别同一个物理纸箱。操作人员仍须核对现场实物。

原质量拆分、退货分段或其他异常数量处理没有提供逐个拆箱的取货选择。本轮不扩展这些页面：无法确定实物分配时，将受影响组成恢复为“包装未核实”，保留真实总量与原质量记录，后续据实核实；不猜测或重复计算箱子。

前端只增加相应输入、展示和整理入口。另修正了本次白色库存详情/包装表单继承导航深色主题导致文字不清的问题，未修改导航样式或全局布局。
