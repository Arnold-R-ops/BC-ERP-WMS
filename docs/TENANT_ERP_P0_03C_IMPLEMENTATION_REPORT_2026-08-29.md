## 1. 本阶段交付结果

P0-03C 已把收货质检接入 P0-02 统一收货与 P0-03A/P0-03B 库存质量真相。收货仍先确认实际到货并形成在库批次；SKU 或租户策略要求质检时，该批次以 `PENDING_INSPECTION` 计入实存但不参与可售、销售预留和出库。免检商品直接进入 `AVAILABLE`。

一次收货事件只生成一张质检任务，任务可包含多个 SKU、批次和库位。质检在原收货库位完成，不强制设置质检专用库位，也不产生额外仓内移动。

## 2. 可选质检策略

- 租户默认质检开关初始为关闭，降低普通租户使用成本。
- SKU 提供 `INHERIT`、`REQUIRED`、`EXEMPT` 三档设置；SKU 明确设置优先于租户默认值。
- 采购收货和“其他入库申请”共用同一套判定，不存在另一条独立直接入库真相。
- 合格库存的放行模式支持 `DIRECT` 和 `REVIEW_REQUIRED`。默认直接放行；开启复核后，隔离数量立即生效，合格数量继续待检并等待另一名用户复核。
- 质检策略由独立权限控制，不与套餐强制绑定；普通角色不会自动获得该权限。

## 3. 质检执行与库存状态

- 支持全检和抽检；本阶段不提供 AQL 自动判定。
- 一次提交可以处理任务中的一个或多个明细，并分别填写合格数量和隔离数量；允许分多次完成。
- 每次提交在一个数据库事务内原子执行：结果、任务进度、批次拆段、质量状态和幂等审计要么全部成功，要么全部回滚。
- 合格数量从 `PENDING_INSPECTION` 转为 `AVAILABLE` 后才唤醒缺货销售分配；隔离数量转为 `QUARANTINED`，仍计入实存但不可售。
- 部分判定沿用 P0-03B 质量段机制，保留商品、原批次、外部批次、生产日期、效期和库位追溯，不要求重新贴标。
- 可选复核实行制审分离，提交人不能批准或驳回自己的放行结果。

## 4. 正式更正与复检

- 已生效的结果不允许修改数量、原因或覆盖历史；录入错误通过新的“更正/复检”任务形成审计链。
- 对已放行库存发起更正时，系统先调用 P0-03B 受控冻结流程，必要时按用户明确确认原子改派尚未开始作业的销售预留，然后转回 `PENDING_INSPECTION`。
- 对隔离库存发起复检时，目标数量直接转为 `PENDING_INSPECTION` 并生成新的复检任务。
- P0-03B 人工冻结仍作为紧急处理入口，不替代正式更正/复检记录。

## 5. 到货月台异常

- 仓库收货页面新增到货异常登记，可记录短到、超到、错货、破损、效期不符和其他异常。
- 可选处置包括等待补送、月台拒收、收货后转质检和仅登记。
- 到货异常只是收货前证据；被月台拒收的数量不会创建库存，也不会伪造质检结果。
- 记录使用登录账号作为操作人，并要求 `Idempotency-Key`，客户端不能填写操作人。

## 6. 权限、租户隔离与隐私

新增五项可独立分配的权限：

- `receiving_inspection:view`
- `receiving_inspection:execute`
- `receiving_inspection:review`
- `receiving_inspection:correct`
- `receiving_inspection:policy`

迁移会为已有租户补齐权限目录，新租户创建时也会获得同一目录，但普通角色不会自动获得权限。接口继续执行租户隔离和仓库范围校验。

仓库质检契约只返回安全作业字段，不返回供应商、采购价格、承运商、运单号或 ASN 编号。质检任务保留采购单号或其他入库申请号作为安全来源参考。
