## 2. 实际失败点

实际流程仅到：

1. Node/pnpm/源码及 r11 指纹核对。
2. 创建新 f2 证据目录并固定预算。
3. pnpm 版本命令：退出 0，输出 11.16.0。
4. `pnpm config get verify-deps-before-run`：退出 0，输出 `undefined`。
5. 专用工具错误地要求第 4 项必须输出 `error`，因此抛出 `Implicit-install prevention not effective`，包装器退出 1，后续未执行。

第 4 项命令回执中的 `PASSED` 仅表示命令正常退出，**不表示配置保护验证通过**。原始 `restore-failure.json` 保持 FAILED，不改写；本补充记录澄清，其异常文字不能直接作为“运行时保护未生效”的结论。

只读核对当前 pnpm 11.16.0 实际代码发现：

- `addSettingsFromWorkspaceManifestToConfig` 将该特殊环境变量赋给运行时 `verifyDepsBeforeRun`，但此赋值没有加入 `explicitlySetKeys`。
- `config get` 的 `lookupConfig` 使用 `explicitlySetKeys` 筛选输出；因此它可能输出 `undefined`，不能据此判断此特殊运行时覆盖没有生效。
- 执行依赖检查的 `error` 分支会抛出 `VERIFY_DEPS_BEFORE_RUN`，而不是运行安装。**本批尚未进行缺依赖的真实合成运行来验证该行为**，不把源码阅读写成行为实测通过。

源码依据为本地工具 `target/platform-validation-tools/pnpm-11.16.0/package/dist/pnpm.mjs`，SHA-256：`6d1d488e4ff9371a32cf4d322a01a8f6998e31b9c97342a77ca2bb179cf3234f`。未修改该工具分发包。
