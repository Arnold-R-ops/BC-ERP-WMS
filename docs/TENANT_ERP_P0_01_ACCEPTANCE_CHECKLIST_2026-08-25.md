## 1. 验收环境

- 使用专用测试数据库和至少两个测试租户，不使用正式租户数据。
- 每个租户至少准备：租户管理员、仓库制单人、复核人、批准人；后三个账号必须是不同用户。
- 准备一个可用批次，记录 `OnHand`、`Reserved`、批次版本、仓库、SKU 和库位；另准备一个数量为零的停用批次。
- 普通租户不授予 `INVENTORY_CORRECTION_APPROVAL`；高端或全功能试用租户授予该权益。
- 浏览器验收可在电脑浏览器完成；手机浏览器只作为可选页面预验收，不构成本 Epic 的设备验收门槛。

本次使用本机专用 `wms_db_test`。浏览器主流程使用已完成业务基线初始化的公司 `1`，账号分别为租户管理员 `201`、仓库制单人 `202`、复核人 `203`、批准人 `204`；数据库隔离与同键跨租户场景使用专用高位测试公司，未使用正式租户数据。测试结束后，公司 `1` 已恢复 `FREE` 套餐、`NONE` 审批模式，试用起止时间已清空。

## 4. 普通租户：NONE 模式

1. 打开租户主界面中的“库存校正”。普通租户不应看到审批模式配置入口。
2. 创建校正单，填写 SKU、库位、已有批次或新批次资料、盘点数量、原因和说明。
3. 确认制单时冻结 `systemQty`、`countedQty` 和 `adjustmentQty = countedQty - systemQty`；`approvalModeSnapshot = NONE` 在直接二次确认时冻结。
4. 由制单人打开影响预览，确认页面显示当前数量、预留数量、预计落账数量、受影响订单和预览失效时间。
5. 二次确认后执行落账。非制单人尝试直接执行应被拒绝。

期望结果：

- [x] 落账数量为“当前数量 + 制单时差异量”，不使用旧盘点数覆盖当前数量。
- [x] 批次数量、库存流水、Outbox 和校正单结果在一个事务内一致。
- [x] 流水包含租户、仓库、SKU、批次、来源单、原因、操作者、前后数量、`postingId` 和幂等键。

## 5. 库存变化与预览失效

1. 创建校正单并获取影响预览。
2. 在另一个受控业务流程中使同一批次的 `OnHand` 或 `Reserved` 发生变化。
3. 使用旧 `previewToken` 执行校正。

期望结果：

- [x] 返回 `409 INVENTORY_CORRECTION_PREVIEW_STALE`，库存、预留、流水和 Outbox 均不变化。
- [x] 重新读取影响预览后显示最新数量。
- [x] 使用新的业务尝试和有效预览，按“最新数量 + 原差异量”落账。

## 6. 预留保护

2. 创建差异量 `-25` 的校正，使预计数量为 `75`。
3. 打开影响预览并尝试落账。

期望结果：

- [x] `canApply = false`，页面显示受影响销售单/预留。
- [x] 后端最终校验仍返回预留冲突，不能只依赖前端按钮禁用。
- [x] 不自动释放或重新分配预留，库存和流水零污染。

## 7. 零差异与停用零批次恢复

零差异：

- [x] `adjustmentQty = 0` 的校正可以完成并保存审计结果。
- [x] 不新增库存数量流水，不新增 `INVENTORY_POSTED` Outbox，批次数量不变。

停用零批次：

- [x] 紧急校正的“现有批次”选择可以看到启用正库存批次和停用零库存批次；普通库存查询仍不显示停用零库存批次。
- [x] 对数量为零的停用批次执行正向校正时，可以通过受控 `INVENTORY_GAIN` 重新激活。
- [x] 对其他停用批次写入或负向校正仍被拒绝。
- [x] 新批次码与同库位已有批次冲突时，预览和最终落账均拒绝，不能创建重复批次身份。

## 8. TWO_PERSON 与 THREE_PERSON

在具备审批权益的测试租户中：

- [x] 普通租户请求启用两人制或三人制时，后端拒绝且不写配置。
- [x] 试用已过期、已取消、欠费或已过期订阅不再获得审批权益；有效全功能试用可以使用审批模式。

## 9. 幂等、并发与恢复

- [x] 同租户、同键、同命令首次执行成功；再次执行重放同一结果，不重复改库存或写流水。
- [x] 同租户、同键、不同命令意图返回 `IDEMPOTENCY_CONFLICT`。
- [x] 两个并发请求使用同键时，只有一个获得执行租约；另一个返回处理中或重放结果。
- [x] 处理租约过期后，新执行者获得不同租约令牌；旧执行者不能覆盖新结果。
- [x] 确定性业务失败使用同键重试时重放同一失败。
- [x] 暂时性失败不形成虚假成功；租约到期后可以安全恢复。
- [x] 两个租户可分别使用相同幂等键，且 PostgreSQL RLS 只能看到本租户记录。

## 10. 事务回滚与不可变审计

分别在库存流水保存和 Outbox 保存处注入异常：

- [x] 批次数量、校正状态、库存流水和 Outbox 全部回滚。
- [x] 重试不会因上次半成品产生重复落账。
- [x] 已落账的库存流水不能由普通业务角色更新或删除。
- [x] 租户清理只能通过受保护的 `app.tenant_purge` 治理路径执行，并由平台审计覆盖。
