## 本次代码

后端：

- `PlatformBrowserBinding.java`：新增服务器随机签发并 HMAC 验证的浏览器分组 Cookie；HttpOnly、SameSite=Strict、无 Domain、路径仅 `/api/platform`，有效期 12 小时，登录初始化可保留同一标识。一般部署使用 Secure；仅请求主机和实际连接对端均为字面量 127.0.0.1 时允许专用非 Secure 本地 Cookie。忽略转发头，非同源 Fetch Metadata 初始化被拒绝。
- `PlatformSessionController.java`：新增 POST `/api/platform/auth/browser-session` 初始化接口，要求特定非简单请求头，不返回认证材料，不授予登录或接口权限。
- `DynamicAuthorizationManager.java`：仅将这个平台初始化路径加入公开路径；既有 Host/平台入口边界不变。
- `PlatformMfaService.java`：MFA 验证、绑定及邀请激活完成后，以有效服务器 Cookie 关联新会话；缺失或伪造 Cookie 时不发放已登记会话。缺失 Cookie 时 MFA 成功记录、挑战消费和会话创建的真实事务回滚与重新初始化后重试已通过 PostgreSQL 验证。
- `PlatformSessionService.java`：保存 Cookie 的 SHA-256 摘要，退出从已认证会话的数据库记录确定分组，不接受客户端指定任意待撤销分组。账号 `FOR NO KEY UPDATE` 锁在任何会话锁之前获取，与登录创建、活动检查协调；组内撤销及审计处于同一事务。审计范围为 `BROWSER_PLATFORM_SESSIONS`，可展示的 operation 为 `BROWSER_LOGOUT`，`sessionsRevoked` 为本次更新行数。普通退出不增加账号安全版本。
- 内部独立会话创建入口仍供既有隔离测试夹具使用，每次生成独立分组；所有真实 HTTP MFA 成功入口改用带有效 Cookie 的创建方法，没有给旧 JWT 自动补会话或自动归组的路径。

前端：

- `browserLogout.ts`：Web Locks 串行化同源浏览器的初始化与认证请求，避免正常并发首登分配不同 Cookie。BroadcastChannel 加 storage 事件通知同账号标签；按账号分别保存非认证性的退出标记，避免不同账号并发写入互相覆盖。通知不携带 JWT、密码、MFA 或 Cookie。通知失败不能阻止向后端提交撤销。
- `storage.ts`、`PlatformAuthProvider.tsx`：JWT 仍使用原有按标签 sessionStorage；退出标记用于清除其他标签及休眠后恢复的旧本地登录。旧退出响应或通知不能清除退出后新建立的登录。网络失败仅报告撤销未确认。
- `api.ts`：认证前准备浏览器 Cookie，明确 same-origin 凭据，限制请求等待时间；普通退出仍携带退出前捕获的 JWT。MFA 响应晚于同账号浏览器退出时，不自动将其装入当前页面登录状态。
