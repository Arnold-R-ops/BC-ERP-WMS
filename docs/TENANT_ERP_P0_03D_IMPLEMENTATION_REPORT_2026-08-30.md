## 1. 本阶段交付结果

P0-03D 已在 P0-03A～P0-03C 的库存质量真相上补齐破损、日期过期和最终实物报废/销毁流程。登记破损或系统标记过期只改变批次的可售质量状态，仍保留实存在库数量；只有仓库人员执行实物报废/销毁时，才通过统一库存记账服务扣减实存在库并生成库存流水。

租户管理端新增“库存治理 → 库存处置”页面，支持破损影响预览、破损登记、处置草稿、提交、可选审批、取消剩余数量、分批执行、执行历史和策略配置。仓库独立端新增“处置”入口，只提供待执行任务和实物执行能力，不展示供应商、采购价格、承运商或运单信息。

## 2. 破损与日期过期

- 可对 `AVAILABLE`、`QUARANTINED`、`RECALL_HOLD` 库存登记破损；`PENDING_INSPECTION` 必须先完成质检判断。
- 部分破损或过期沿用质量段机制，保留原商品、批次、外部批次、生产日期、效期和原库位，不要求重新贴标，也不触发仓内移动。
- 商品在效期日期当天仍可使用，从次日开始过期。自动任务按各租户业务时区计算；租户未设置时使用标准 IANA 时区 `Europe/London`，自动处理 GMT/BST。
- 自动过期策略默认开启，可由具备独立策略权限的租户管理员关闭。任务每小时按活跃租户检查，写入 `EXPIRED` 及审计证据，但不自动报废、销毁或扣减库存。
- 临期继续沿用提醒语义，不自动冻结、促销或折价。

## 3. 销售预留保护

破损或过期触及已预留库存时，系统先生成影响预览并按出库进度处理：

- 尚未开始拣货：优先按 FEFO 寻找其他可售批次并原子改派；不足部分释放原预留和待拣任务，并生成欠货。
- 已开始拣货：不再迁移预留；任务转为 `QUALITY_EXCEPTION` 并阻止继续出库，受影响数量进入欠货。
- 已发货：本阶段不回写已完成出库，留给后续召回/RMA 流程。
- 客户端必须明确确认破损造成的改派、欠货和拣货异常影响；自动过期按租户策略受控执行。

## 4. 最终报废/销毁

- 本阶段只交付 `SCRAP_DESTROY`，不实现退供应商、返工或其他处置类型。
- 单据状态为 `DRAFT`、`PENDING_REVIEW`、`READY_TO_EXECUTE`、`PARTIALLY_EXECUTED`、`COMPLETED`、`REJECTED`、`CANCELLED`。
- 普通租户默认“填写原因后直接进入待执行”；租户可独立开启双人审批，不与套餐绑定。开启后制单人不能审批自己的单据。
- 草稿可以保存、由制单人提交或取消；提交时会重新锁定并校验来源批次状态、实存和预留。
- 支持多次部分执行。每次提交中的所有明细、库存扣减、库存流水、执行证据、处置进度、库位占用刷新、幂等记录和 Outbox 在同一事务中原子提交。
- 未执行或部分执行后可取消剩余数量；已执行数量和流水不可修改或删除。后续差错只能另建正式更正记录，不能覆盖历史。
- 执行人只取自登录账号，客户端请求没有操作人字段。
- 执行事件向财务/集成层发出 `PENDING_EXTERNAL_ACCOUNTING` 语义，不在本阶段伪造成本、估值或会计分录。

## 5. 权限、租户隔离与审计

新增六项可独立分配的权限，普通用户默认不会自动获得：

- `inventory_disposition:view`
- `inventory_disposition:report`
- `inventory_disposition:create`
- `inventory_disposition:execute`
- `inventory_disposition:review`
- `inventory_disposition:policy`

迁移会为已有租户补齐权限目录，新租户权限目录初始化也使用同一清单。所有新业务表使用租户复合外键并启用、强制执行 RLS。实物执行、执行明细和销售预留影响记录由数据库触发器保护为追加式证据；只有受控租户清理流程允许删除。
