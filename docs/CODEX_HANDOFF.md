## 已确认业务规则

- `WAREHOUSE_STAFF` 只授予仓库作业所需最小权限，不应暴露销售、采购或 IAM。
- 断网或后端不可达时禁止扫码、手动录入、刷新和库存提交；不建立离线写入队列。
- Shopify 仅做 Shopify→WMS 只读同步，不做 WMS→Shopify 回写。
- 库存写入前必须说明订单、仓库、库位、SKU、批次、预留、流水基线与预期影响。
- 采购验收单保持 `ORDERING`，未经明确授权不得确认 ASN 或收货。
- 权限模型按步骤评审；当前先做小公司模式，角色与权限包第一版视为同一对象。
- 禁用角色不再贡献任何直接或继承权限，且继承遍历在禁用角色处终止。
- 新自定义权限包复用 `description` 作为必填用途说明；适用人数不影响授权且实际人数实时统计；风险说明由权限等级自动生成，含高风险权限时另填操作理由。
- 权限申请仅允许 `SUPER_ADMIN`、`SECURITY_ADMIN` 代目标用户发起，员工没有自助申请入口；只能申请启用、可分配的普通业务模板或 `CUSTOM + APPROVED + ACTIVE` 包，受保护特权角色不可申请。
- 批准只新增请求角色，保留原角色集和默认角色；`WAREHOUSE_STAFF` 申请必须附带启用仓库。普通风险允许同一有权 IAM 管理员提交与复核；高风险必须由不同申请人的另一名 `SUPER_ADMIN` 批准，`SECURITY_ADMIN` 只能驳回高风险申请，驳回意见必填。
- 复制只保存源包当时的正式有效权限为目标直接权限，不复制继承、用户或临时授权；源包后续变化不传播。
- 高风险复制需填写业务理由、勾选风险确认并输入目标包编码；快照变化返回冲突，受保护权限直接阻断。
- 新包默认草稿且停用；批准后仍停用，必须显式输入包编码启用。仅已批准且启用的自定义包可以分配给用户。
- 空白新建只允许选择启用、允许自定义分配且非 `CRITICAL` 的权限；受保护权限前端隐藏、后端拒绝，模板复制仍作为可选快捷方式保留。
- 启用包不可原地编辑，必须复制形成独立新版本；停用角色不贡献权限，停用动作不能被已退役的历史权限阻断。
- 用户含 `WAREHOUSE_STAFF` 时必须分配一个或多个启用仓库；范围仅在该角色为当前激活角色时生效，移除角色即清空仓库分配。
- 跨仓入库单采用“全部包含”规则；只分配其中一个目标仓库不能查看或操作整单。缺少仓库分配或任务仓库数据异常均失败关闭。
- `WAREHOUSE_ADMIN` 保持不限仓；临时跨仓授权尚未实现，后续必须另立规则和审批任务。
